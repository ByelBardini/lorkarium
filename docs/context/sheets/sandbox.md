# Fichas — sandbox do client

O iframe onde roda o código do autor da ficha e o SDK que vive dentro dele. Hub: [`../sheets.md`](../sheets.md). A ponte do **host** (validar pelo `sheetFrameMessageDto`, limite de frequência, comandos) fica em [`../client/sheets.md`](../client/sheets.md).

## Arquivos (`client/src/sheet-sandbox/`)

- `sheet-srcdoc.ts` (puro) — `sheetContentSecurityPolicy(scriptHashes)` (um `'sha256-…'` por hash; lista vazia → `script-src 'none'`; hash que não é base64 de 44 caracteres → `RangeError` citando o valor), `SHEET_BASE_STYLE`, `SheetSource { files, assets? }`, `buildSheetSrcdoc(source): string` (arquivos que não montam a página → `SheetBuildError`), `sheetScriptLayoutOf(source)` (onde cada `.js` começa, medido uma vez por objeto), `authorScriptPositionOf(source, positions)` (posição do `srcdoc` → `{ path, line, column }` do arquivo JS, ou `null`) e `sameSheetSource`. Includes e `asset:` moram em `sheet-page-assembly.ts` ([`arquivos.md`](arquivos.md)). Importa o bootstrap e o `client/src/lib/sha256.ts` (SHA-256 síncrono em TS puro, `sha256Base64(text)` sobre os bytes UTF-8; o `crypto.subtle` é assíncrono e o `srcdoc` nasce no render) por caminho **relativo**, nunca `@/`: o e2e importa este arquivo de fora do client.
- `sheet-bridge-bootstrap.ts` (puro) — `SHEET_BRIDGE_BOOTSTRAP` (o texto do script), `SHEET_PORT_HANDOFF` (`'lorkarium:port'`) e os tipos `LorkariumSdk`, `SheetSdkPort`, `SheetFrameScope`, `SheetFrameMessageEvent`, `SheetFrameCharacter`; as formas que o SDK recebe e devolve (`SheetBarChange`, `SheetDiceRequest`, `SheetFrameRoll`, `SheetFrameRolledDie`, `SheetImageInput`, `SheetFrameImage`) moram em `sheet-sdk-shapes.ts` (só tipos, fora do teto de 500 linhas do bootstrap). Tipos estruturais, sem DOM, para o `tsc` do e2e (só tipos do Node).
- `sheet-html-sanitizer.ts` (puro) — `SHEET_HTML_SANITIZER_SOURCE` (o texto de `createHtmlSanitizer(DOMParser)`, serializado como o bootstrap) e os tipos estruturais `SheetHtmlNode`/`SheetHtmlElement`/`SheetHtmlDocument`/`SheetHtmlParserClass`/`SheetHtmlSanitizer`. Fora do bootstrap só para o arquivo dele caber em 500 linhas: o `SHEET_BRIDGE_BOOTSTRAP` chama `installLorkariumSdk(window, limites, (sanitizador)(window.DOMParser), createFrameConsole)`.
- `sheet-frame-console.ts` (puro) — `SHEET_FRAME_CONSOLE_SOURCE` (o texto de `createFrameConsole(scope, limites, send)` → `{ logged, onScriptError, onRejection, wrap }`, serializado do mesmo jeito) e os tipos `SheetFrameConsoleCapture`/`SheetFrameConsoleFactory`. - `sheet-frame.tsx` — `SheetFrame({ srcdoc, title, onConnect(port), onReloaded(), createChannel? })`, `SheetChannel` e `SheetSourceFrame({ source, … })`: monta o `srcdoc` **uma vez por montagem** (`useState`); a sala (`SheetSandboxView`, `key` = versão + "Recarregar") e a prévia (`key` = cada rodada) usam este, então código novo é frame novo.

## Flags do iframe

`<iframe sandbox="allow-scripts" allow="" referrerpolicy="no-referrer" srcdoc=…>`, sem `src`.

- **Sem `allow-same-origin`:** a origem é opaca (`null`); o frame não lê o pai nem o cookie/storage do app. Somar `allow-same-origin` a `allow-scripts` anula o sandbox (o frame tira o próprio atributo). Nunca acrescentar.
- Sem `allow-popups`, `allow-forms`, `allow-top-navigation*`, `allow-modals`: `window.open` devolve `null`, `form.submit()` não sai, `top.location = …` lança.
- `allow=""`: nenhuma permissão (câmera, microfone, tela cheia, clipboard…).
- O `srcdoc` é lido **uma vez** (`useState`): trocar a prop não recarrega o frame (recarregar pareceria o 2º `load`). Código novo = `key` novo.

## CSP (primeiro `<meta>` do `srcdoc`)

```
default-src 'none'; script-src 'sha256-<bootstrap>' 'sha256-<1º .js>' …; script-src-attr 'none'; style-src 'unsafe-inline'; img-src data: blob:; font-src data:; form-action 'none'; base-uri 'none'
```

Só executa script cujo texto tem um dos hashes listados: o bootstrap (hash calculado uma vez, constante do módulo) e cada `.js` do autor, exatamente o texto entre `<script>` e `</script>` (com a quebra de linha inicial e o escape do `</script`). Os `<script>` saem sem atributo. HTML que chega **dos dados** (texto rico gravado por um jogador, mostrado por `innerHTML`) nunca executa: `on*` (`script-src-attr 'none'`), `<script>` criado pelo código da ficha, `href="javascript:…"`. Nada de `'nonce-'`, `'unsafe-inline'` nem `'strict-dynamic'` em `script-src`. O navegador faz o hash **depois** do pré-processamento do HTML (CR LF e CR → LF; U+0000 dentro de script → U+FFFD): o host normaliza o JS do autor antes de embutir, e o embutido e o hash são o mesmo texto (a linha do erro conta as linhas já normalizadas). O CSS segue livre (`style-src 'unsafe-inline'`). O autor liga eventos por `addEventListener`; propriedade `el.onclick = …` no JS dele funciona (não é atributo).

Sem rede nenhuma: `fetch`, imagem, fonte, `<link>` e `import()` externos são bloqueados antes de sair. Imagem e fonte só por `data:`/`blob:` (a do token chega em bytes pelo `state`, B6). O CSP do `srcdoc` **não** cobre a navegação do próprio frame (o `navigate-to` saiu da especificação): quem a barra é o `frame-src 'self'` do **pai**, um `<meta>` no `client/index.html` — o CSP3 confere o `frame-src` do documento que embute em toda navegação do iframe, inclusive a que o próprio frame pede. O `srcdoc` continua permitido. O 2º `load` (a navegação recusada carrega a página de erro) ainda destrói o frame e mostra "Ficha recarregada".

## Ordem do `srcdoc`

`<!doctype html><html><head><meta charset="utf-8">` → `<meta http-equiv="Content-Security-Policy" …>` → `<script>` bootstrap → `<style>` `SHEET_BASE_STYLE` → um `<style>` por arquivo `.css`, na ordem da lista (com `asset:` → `data:`) → `</head><body>` `index.html` com os `<lk-include>` expandidos (e `asset:` → `data:`) → para cada `.js`, na ordem: `<script>` + quebra de linha → o JS → `</script>` → `</body></html>`.

- O bootstrap roda antes de qualquer código do autor; o JS do autor roda depois do HTML (o DOM já existe).
- O JS do autor tem `</script` → `<\/script` e `<!--` → `<\!--` (o `<!--` seguido de `<script` faria o parser pular o fechamento); o CSS tem `</style` → `<\/style`. Dentro de string JS e de CSS o significado é o mesmo. O HTML do autor entra como está (só mexe no próprio documento).
- Um `<meta>` de CSP do autor só **restringe** mais (as políticas se somam).
- **Estilo base** (`SHEET_BASE_STYLE`): `:root { color-scheme: dark; background: #101216; color: #eae5da; font-family: system-ui }`. **Decisão:** no CSS base do `srcdoc`, não no código inicial, porque o bug (texto claro do `.ficha` sobre o branco do frame) atinge qualquer modelo escrito para a sala escura, e um modelo já salvo não muda; o CSS do autor vem depois com o mesmo peso e sobrescreve. O `STARTER_SHEET_SOURCE` não mudou (armadilha do e2e no hub).
- **Linha do erro:** `sheetScriptLayoutOf` mede o que vem antes de cada JS (sem os assets: base64 não tem quebra de linha); a quebra depois de cada `<script>` põe o JS na coluna 0 da própria linha; o `<meta>` da política não tem quebra, então a conta não depende dos hashes. `authorScriptPositionOf` pega a 1ª posição (a do evento, depois a pilha) que cai dentro de um JS e a devolve como arquivo, linha e coluna dele. Posição no bootstrap, no HTML ou além do fim do JS → `null` (a linha não aparece).

## Bootstrap e SDK (`window.lorkarium`)

O bootstrap é a função `installLorkariumSdk` serializada por `toString()`: ela não pode citar nada de fora do próprio corpo (o spec roda o texto serializado por `new Function` para provar). Começa por `'use strict'`.

- Pedidos → `Promise<undefined>`: `ready()` ("estou pronta para receber dados": sem ele nenhum `state` chega), `bars.adjust(nomeOuId, change)` (manda `bar` como veio; `change` = `{ op: 'add', amount }` ou `{ op: 'set' | 'max' | 'temp', value }`, a forma do `barChangeDto`), `values.set(changes)`, `values.patch([{ path, value }])`, `bars.spend([{ bar, amount }])`, `character.set({ armorClass?, difficultyClass? })` e `character.setImage(imagem)`; `bars.create({ label, max, color? })` → `Promise<{ barId, created }>` (permissão `character:bars`; `created: false` = já havia), `assets.upload(imagem)` → `Promise<{ assetId }>` `assets.read(assetId)` → `Promise<{ type, bytes }>`, `documents.list()`/`tabs(id)`/`readTab(id, aba)` (desembrulhados, cópia JSON; [`documentos.md`](documentos.md)) e `dice.roll({ expression, label?, visibility? })` → `Promise<{ expression, total, dice }>`, que resolve quando os dados param (o valor vem do `value` do `result`; só as três formas do contrato chegam ao autor, congeladas, cada dado só com `sides`, `value`, `status` e `success`; outra forma → `undefined`). `imagem` é um `File`/`Blob` (lido por `arrayBuffer()`, com o `type` dele) ou `{ type, bytes }` com `ArrayBuffer` ou `ArrayBufferView`; os bytes vão como **cópia** nova por clone estruturado (fora do JSON); outra coisa → `TypeError` sem enviar. `onState(listener)` → função que desinscreve, e o ouvinte novo recebe o último `state` na hora.
- Leituras síncronas do último `state`, sem pedido ao host, sempre **cópia JSON** (mudar o devolvido não muda a próxima leitura): `values.get(chave)` (só chave própria: `values.get('toString')` é `undefined`; `undefined` sem a chave ou antes do 1º `state`), `values.all()` (`{}` antes), `bars.list()` (`[]` antes ou sem token) e `bars.get(nomeOuId)` (id exato, senão o rótulo sem caixa/acento/espaço nas pontas; `undefined` sem barra; duas com o nome → **lança** `Error` de `code` `BAR_AMBIGUOUS`). A regra repete a do `resolveSheetBar` do host porque o bootstrap não importa nada; quem vale é a do host.
- `html.sanitize(html)` → string, síncrono, sem pedido ao host: limpa o texto rico antes do `innerHTML`. Lê com o `DOMParser` (documento inerte: nada roda nem carrega) capturado antes do código do autor, e copia só: `p br hr strong b em i u s span blockquote ul ol li h1–h6 img`; `div` vira `p`; `img` só com `src` `blob:` ou `data:image/` (senão some inteira); `style` só `color` (hex, nome, `rgb/hsl`) e `text-align`; nenhum outro atributo (`on*`, `href`, `id`, `class`, `data-*`). `script style iframe object embed svg math template noscript textarea select link meta title frame frameset` somem com o conteúdo; outra tag desconhecida (`a`, `marquee`) dá lugar ao texto. Não-string → `TypeError` citando o tipo. É conveniência do autor (formatação previsível): quem impede o dado de executar é o CSP por hash.
- `lists.add(lista, item?)` → `Promise<id>`, `lists.remove(lista, id)` e `lists.items(lista)` (síncrono): listas repetíveis com id `[a-z0-9]{8}` estável, por `values.patch`; e os atributos `data-lk`/`data-lk-roll` — regra inteira em [`ligacao-declarativa.md`](ligacao-declarativa.md).
- `character.get()` → cópia do `state.character` (`{ name, armorClass, difficultyClass }`) ou `null` (antes do 1º `state`, token solto, sem dono).
- Ficha sem token: o `state` chega com `token: null`, `bars: []` e `character: null`.
- Mensagens frame → host (nomes do [`contratos.md`](contratos.md)): `{ type, requestId, … }` com `type` ∈ `ready`, `bars.adjust`, `bars.spend`, `bars.create`, `dice.roll`, `values.set`, `values.patch`, `character.set`, `character.setImage`, `assets.upload`, `assets.read`, `documents.list`, `documents.tabs`, `documents.readTab`; `requestId` = contador (`'1'`, `'2'`…). Nunca `tokenId`, `campaignId` nem `sheetId`; o `dice.roll` só leva `expression`, `label` e `visibility`, mesmo que o autor passe mais.
- Host → frame: `state` (o SDK entrega `{ token, bars, values, canEdit, character }`), `result` (resolve) e `error` (rejeita com `Error` de `code` e `message`). Outro `type`, corpo que não é objeto, `requestId` desconhecido ou já respondido → ignorado. `error` com `requestId: null` não chega ao autor.
- Pedidos feitos antes da porta ficam na fila e saem na ordem quando ela chega.
- Fechado e protegido: `JSON.parse`/`stringify`, `Number.isFinite`, `Object.freeze` e `console.error` são capturados antes do código do autor; o payload sai como **cópia JSON** (mudar o objeto depois não muda o enviado; função, `NaN` e `Infinity` rejeitam com `TypeError` sem enviar nada — o `JSON` puro trocaria `NaN` por `null`, que apaga a chave); `window.lorkarium` é não gravável e não configurável, e o SDK e os sub-objetos estão congelados. Ouvinte de `onState` que lança vai ao `console.error` sem impedir os outros.
- **Console** (`SHEET_CONSOLE_FRAME_LIMITS`: linha até 2000 caracteres, 20 linhas por segundo, 8 posições — os do contrato): o bootstrap troca `console.log/info/warn/error/debug` por um embrulho que **chama o original** e manda `{ type: 'console', level, message, at }`; escuta `error` do `window` (`message`, `lineno`/`colno` e a pilha do `error`) e `unhandledrejection` (`"Uncaught (in promise) " + motivo`; a recusa do SDK não tratada sai como `Error CODE: mensagem`). O texto é seguro: ciclo → `[circular]`, função → `[function nome]`, nó do DOM → `<tag>`, `bigint`/`symbol` em texto, getter que lança → `[unreadable value]`; nada além de string vai ao `postMessage`. Linha longa é cortada com `…`; acima do limite, as linhas da janela viram **um** `console.dropped` com a contagem (janela fixa). As posições saem do `about:srcdoc:L:C` da pilha. O console nunca quebra o código do autor.
- O autor divide o realm com o SDK: pode pegar a porta ele mesmo. Não é falha — a porta só faz o que o SDK faz, e o host/servidor reautorizam (o "gesto do usuário" não é provável; a defesa é o limite de frequência da B6).

## Porta e 2º `load` (`SheetFrame`)

- 1º `load`: cria o `MessageChannel`, manda `{ type: 'lorkarium:port' }` com o `port2` por `contentWindow.postMessage(…, '*', [port2])` (origem opaca não pode ser alvo nomeado) e entrega o `port1` ao pai por `onConnect`. O bootstrap só aceita a primeira entrega, vinda de uma janela **fora do frame** (sobe pelos `parent` até a do topo sem passar pelo próprio frame; nunca o frame nem um filho dele), com o `type` certo e exatamente uma porta. Não é `source === parent`: o `event.source` é quem chamou o `postMessage`, e na janela da ficha é a janela da sala (o portal), não a auxiliar que embute o frame.
- 2º `load` (o código do autor navegou o frame — `location = …`, `<meta refresh>`): fecha as duas pontas, desmonta o iframe e chama `onReloaded()`; o pai mostra "Ficha recarregada". Nenhuma porta sai depois do 1º `load`. Desmontar também fecha o canal.

## Pendente: medição de processo

Decide se o cão de guarda da B7 basta ou se o "modo seguro" (ficha sem script) vira requisito da B7.

1. Uma ficha com `while (true) {}` atrás de um botão (para o frame carregar antes de travar), montada por `buildSheetSrcdoc` numa página do app.
2. **Chrome:** abrir `chrome://process-internals` → "Frame Trees"; conferir se o frame da ficha (origem opaca) está num processo diferente do da página. Clicar o botão e ver se a sala segue respondendo (rolar o mapa, abrir um menu).
3. **Casca desktop (WebView2):** `pnpm desktop:dev` e inspecionar pela porta CDP 9333 (ver `docs/context/desktop.md`); mesmo procedimento, abrindo `chrome://process-internals` (ou `edge://process-internals`) num alvo do DevTools remoto da casca.
4. Registrar aqui: navegador, versão, mesmo processo ou não, e se a sala travou.

## Armadilhas

- **Nonce herda para `import()`: o CSP da ficha usa hash, nunca nonce.** Pelo HTML, o `import()` de um script com nonce leva o nonce junto, então `import('https://cdn…')` do autor saía para a rede com `script-src 'nonce-…'` (os e2e do `import()` de CDN pegaram o pedido na rota). Com `'sha256-…'` o mesmo `import()` dá `TypeError` sem pedido. Script embutido que não bate com o hash (texto sem a normalização, escape diferente) simplesmente não roda: a ficha fica muda até o cão de guarda.
- **O frame herda o CSP do pai.** O app tem só `frame-src 'self'` (`client/index.html`). Tirá-lo reabre a navegação do frame para fora (vaza o IP de quem olha); um CSP maior no app precisa manter `frame-src 'self'` e permitir o `srcdoc` (`about:srcdoc`), senão toda ficha some sem erro visível; e o CSP do pai se soma ao do `srcdoc` dentro do frame. Servir o app com um cabeçalho CSP no server é o reforço natural (o `<meta>` vale também no `pnpm dev` e na casca).
- **Nunca `allow-same-origin`** junto de `allow-scripts` (ver Flags).
- **O bootstrap não importa nada:** qualquer referência fora de `installLorkariumSdk` e de `createHtmlSanitizer` (constante do módulo, helper, Zod) quebra só dentro do frame. O spec do bootstrap roda o texto serializado e pega isso.

# Fichas — servidor

Hub: [`../sheets.md`](../sheets.md). Módulo `server/src/modules/sheets/`. Contratos em [`contratos.md`](contratos.md).

## Tabelas

- `sheet_templates` (`0072_sheet_templates`, `sheet-templates.po.ts`): `id`, `campaign_id` (cascade), `folder_id` nulo = raiz, `name` (`CHECK` 1–60), `files` (JSONB, da `0099_sheet_template_files`, que converteu as antigas `html`/`css`/`js`; ver [`arquivos.md`](arquivos.md)), `manifest` (JSONB `NOT NULL`, padrão `{"permissions":[],"bars":[]}`, da `0098_sheet_template_manifest`; tipado no PO por `SheetTemplateManifestPo`), `version` (≥ 0, começa em 0), `created_by` (→ `users`, set null), timestamps. Único `(campaign_id, id)`, índice `(campaign_id, folder_id)`. FK composta `sheet_templates_folder_fk` (`campaign_id`, `folder_id`) → `scene_folders` **editada à mão** para `ON DELETE SET NULL ("folder_id")` (a armadilha da `0033`, ver [`../library.md`](../library.md)).
- `token_sheets` (`0073_token_sheets` + `0074_sheets_in_library`, `sheets.po.ts`): `id`, `campaign_id` (cascade), `template_id`, `name` (`CHECK` `token_sheets_name_length` 1–60), `folder_id` nulo = raiz, `token_id` **nulo** = sem token (→ `tokens`, **set null**: apagar o token deixa a ficha na biblioteca, sem dono), `visibility` (enum `sheet_visibility`: `controllers` padrão | `table`), `values` JSONB (`{}`), `version` (≥ 0), timestamps. **Várias fichas por token** (sem índice único em `token_id`). Índices `(campaign_id, template_id)` (a contagem "em uso"), `(campaign_id, token_id)` e `(campaign_id, folder_id)`. FK composta `token_sheets_template_fk` → `sheet_templates` **restrict**; FK composta `token_sheets_folder_fk` → `scene_folders` **editada à mão** para `ON DELETE SET NULL ("folder_id")`.
- `0074` (gerada e editada à mão): `name` entra nulo, é preenchido com o nome do modelo (`UPDATE … FROM sheet_templates`) e só então vira `NOT NULL`; a FK de `token_id` troca cascade por set null.
- `sheet_actions`: recibos por `(campaign_id, user_id, action_id)`, como `library_document_actions` (operação, SHA-256 canônico do pedido pelo `commandFingerprint` do documents, recibo sem valores).
- `token_sheets.character_id` (`0075_characters`): a ficha do personagem (FK composta set null, `CHECK token_sheets_one_holder`); a migração moveu para lá as fichas das âncoras, e é onde toda ficha de jogador nasce. `characters.main_sheet_id` aponta a principal. Ver [`../characters/fichas.md`](../characters/fichas.md).
- `sheet_assets` (`0097_sheet_images`, `sheet-assets.po.ts`): `(campaign_id, sheet_id, asset_id)`, PK nos três, índice `(campaign_id, asset_id)`; FK composta `sheet_assets_sheet_fk` → `token_sheets` **cascade** (excluir a ficha corta a leitura das imagens) e `sheet_assets_asset_fk` → `assets` cascade. A mesma migração soma `sheet_image` ao `asset_purpose`.
- Exportadas no `schema.ts`; `truncateAllTables` inclui as três e a `sheet_assets`. O `values` é tipado no PO por `SheetValuesPo` (o JSON que o orçamento do contrato deixou entrar), para o PO não importar DTO.

## Modelos

- `SheetTemplateBo(access)`: `requireAuthor` (só mestre, co-mestre incluso; espectador e jogador → `FORBIDDEN`), `requireVersion` (→ `SHEET_TEMPLATE_VERSION_CONFLICT` "version N; expected M"), `requireUnused(template, n)` (→ `SHEET_TEMPLATE_IN_USE` "is used by N sheets; expected none"; conta **todas** as fichas, com ou sem dono), `requireFolder` (→ `FOLDER_NOT_FOUND`).
- Manifesto: o create grava o que veio ou `emptySheetTemplateManifest()`; o update troca o manifesto inteiro (só ele já soma a versão); o mapper relê a coluna pelo `sheetTemplateManifestDto` (`toSheetTemplateManifestDto`), então uma lista que o manifesto guardado não tinha volta vazia. Sai no `sheetTemplateDto` e no `sheetTemplateCodeDto` da leitura da ficha.
- `SheetTemplatesService` (`get`, `create`, `update`, `delete`): `memberAccessOf` → `requireAuthor` **antes** de qualquer trava → transação com `CampaignsDao.lockById` → trabalho → commit → `library:changed`. Recusa não publica. Toda gravação soma a versão; `delete` conta as fichas (`SheetsDao.countOfTemplate`) dentro da trava.
- Biblioteca: `LibraryService.deleteFolder` chama `SheetTemplatesDao.moveFromFolder` **e** `SheetsDao.moveFromFolder` (sobem ao pai na mesma transação, **sem** somar a versão). O agregado `GET /campaigns/:id/library` (`LibraryImageService.list`) leva `sheetTemplates` (resumo, sem código) **só ao mestre** e `sheets` (resumos, ver abaixo).

## Fichas na biblioteca

- **Dono** (`holder`): ninguém, um token solto ou um **personagem** (`token_sheets.character_id`; detalhe em [`../characters/fichas.md`](../characters/fichas.md)). `{ memberId }` = o personagem do jogador; `{ tokenId }` de um token ligado = o personagem dele; de um solto = o token. Nada é criado.
- `SheetHolderService` (`sheet-holder.service.ts`, sem deps): `resolve(daos, campaignId, holder)` → `SheetHolderPlacePo | null` (`{ token } | { character }`), `placeOfSheet(daos, sheet)`, `sheetsOf(daos, campaignId, place)`; `characterPlaceIn` → `CHARACTER_NOT_FOUND`. Regras no `SheetItemBo`: `requireGridToken` (outra mesa → `TOKEN_NOT_FOUND`), `requirePlayerCharacter` (personagem que a mesa vê; mestre sem personagem, espectador, estranho → `MEMBER_NOT_FOUND`).
- `SheetItemBo(campaignId)`: `requireFolder` (→ `FOLDER_NOT_FOUND`), `requireGridToken`, `requirePlayerCharacter`, `requireHolder` (→ `{ tokenId } | { characterId }`; sem dono → `SHEET_HAS_NO_TOKEN` "Sheet X has no holder; expected a sheet held by a token or a character"), `mainSheetWritesOf` (a regra da ficha principal).
- `SheetsDao`: `find`, `listOfToken`, `listOfCharacter` (ordem de criação), `listOfCampaign`, `countOfTemplate`, `insert`, `patchValues`, `update` (`SheetChangesPo`: `name`, `folderId`, `tokenId`, `characterId`, `visibility`, `templateId` + versão), `delete`, `moveFromFolder`, `placeOf`/`placesOf` (`TokenPlacePo`: token, `characterId` do token, cena, `kind`, visibilidade, é o grid do grupo, controladores; duas consultas para qualquer número de tokens), `characterPlacesOf`/`characterPlaceOfUser` (`CharacterPlacePo`, pelo `CharactersDao` no mesmo executor), `holdersOf(mesa, fichas)` (`SheetPlacesPo { tokens, characters }`), `action`, `recordAction`. Não lê mais `member_cards`.
- `SheetAccessBo(access, { sheetId, visibility, holder })` (por `toSheetAccessBo(access, sheet, place | null)`): `holder` = `{ token: TokenControl, seen }` (grid pelo `SceneAccessBo.canSee`) ou `{ character: CharacterSeat }` (visto e controlado pelo `CharacterBo`: personagem guardado → só mestres) ou `null` (**sem dono** → só mestres leem, escrevem e gerenciam). `canRead` = vê o dono **e** (controla, ou `table`); `canEdit` = lê e controla; `canManage` = lê e é mestre. Ilegível → `SHEET_NOT_FOUND` (nunca 403); legível sem edição → `FORBIDDEN` ("control of its holder").
- `SheetsService` (`get`, `listOfToken`, `listOfCharacter`, `create`, `updateValues`, `update`, `delete`; deps `read`, `transaction`, `snapshot`, `clock`, `publisher` (`sheet:changed`), `library` (`library:changed`), `characterPublisher` (`character:changed`), `board` (`token:updated`, o `boardPublisher` do `buildApp`), `holders`): escrita trava a **mesa** (`lockById`). Recibo idempotente: mesmo `actionId` + mesmo pedido devolve o recibo com o estado atual e reautoriza (sem publicar nem mexer na principal de novo); pedido diferente → `SHEET_ACTION_REUSED`.
- **Ficha principal**: `create`, `update` com `holder` e `delete` chamam `keepMainSheet` (`main-sheet-writes.ts`) na mesma transação: primeira ficha de um personagem → `main_sheet_id`; a principal que sai → `null`; trava os personagens (a mesma linha de `campaigns`, já travada) e soma a versão deles só se algo mudou.
- **Barras do manifesto**: `create` com dono e `update` com `holder` (não `null`) chamam `giveManifestBars` (`manifest-bar-writes.ts`) na mesma transação, depois da principal: as barras do `manifest.bars` do modelo que o dono não tem (pelo `missingManifestBars` do game-core, rótulo sem acento/caixa) entram cheias (`current = max`, `everyone`, `number`) depois das dele, até 8 (`MAX_BARS_PER_TOKEN`); as de fora vão no recibo (`skippedBars`, rótulos na ordem do modelo). Personagem → `CharactersDao.replaceBars` (existentes com o valor atual + novas) e **uma** versão dos personagens com a principal; token solto → trava o grid (`lockInCampaign`), `TokenHangingDao.replaceBarsAndControllers` (controladores mantidos) e soma a versão do grid. Tirar do dono, nada faltando ou manifesto vazio não grava nem soma versão; existente nunca muda. Mapper: `toManifestBarInputsPo` (`sheet-manifest-bars.mapper.ts`).
- `listOfToken`: token ligado → as fichas do personagem; `listOfCharacter`: personagem de outra mesa ou que o leitor não vê → `CHARACTER_NOT_FOUND`.
- Valores: `patchValues` é um `UPDATE` só, `values = (values || set) - removed::text[]`, versão + 1. O resultado é conferido de novo com `sheetValuesDto`; estourou → `ZodError` → 400 e a transação desfaz.
- Valores por caminho (pedido com `patches`): sob a trava da mesa, o service mescla na ficha lida (`applySheetValueEdits` do contracts, a mesma regra que o client mostra: `changes` primeiro, depois cada caminho), confere com `sheetValuesDto` **antes** de gravar e grava a árvore inteira por `SheetsDao.replaceValues` (versão + 1). A trava serializa as escritas da mesa, então dois caminhos diferentes nunca se apagam. Sem `patches`, segue o `patchValues`. Mesmo recibo, mesmo `sheet:changed`.
- **Publicações** (depois do commit, nessa ordem): `sheet:changed { campaignId, sheetId, version, at }` (sem valores) a cada escrita aplicada; `library:changed` em criar, renomear, mover, trocar dono, visibilidade, modelo e excluir; `character:changed` dos personagens cuja principal ou barras mudaram; `token:updated` do token solto que ganhou barras (`publishTokenChange`, com o véu de token oculto). **Valores só `sheet:changed`.** Porta `SheetPublisherPort`, adaptador `SocketIoSheetPublisher` (`RealtimeOutlets.sheetPublisher`); `RealtimeOutlets.characterPublisher` é o mesmo `SocketIoCharacterPublisher` dos comandos do board (`build-app.ts`).
- Agregado: `LibraryImageService.list` lê `SheetsDao.listOfCampaign` + `holdersOf` e filtra por `readableSheetSummaries` (mestre todas; jogador e espectador as que leem; ninguém lê uma sem dono); as pastas delas entram nos ancestrais visíveis.

## Imagens da ficha

- `sheet-images.routes.ts` (plugin próprio `createSheetImagesModule({ db, assets })`, registrado no `buildApp` depois do das fichas): parser cru para os tipos do `ASSET_MIME_TYPES`, `bodyLimit` de 20 MiB, e no **`onRequest`** a sessão e depois `SheetImagesService.authorizeSender`: quem só lê a ficha recebe 403 antes de o corpo ser lido (até um corpo acima de 20 MiB). 20 envios por minuto por usuário no `preParsing`.
- `SheetImagesService.upload`: `requireEdit` num snapshot → `AssetsService.uploadSheetImage` (processa e grava fora de trava) → transação com `lockById` da mesa, `requireEdit` de novo e `SheetAssetsDao.associate`. Direito perdido no meio (ficha excluída, controle tirado) recusa e deixa um asset órfão que ninguém lê. Não publica evento: a ficha guarda o id nos valores.
- `SheetAssetReadPolicy` (`createSheetAssetReadPolicy(db)`, composta no `readPolicy` do `buildApp` para `purpose = sheet_image`): lê quem lê **alguma** ficha associada (`sheetRulesOf` + `canRead`). Regra de finalidade e cache em [`../assets.md`](../assets.md) (Imagens da ficha).

## Barras pela ficha

- `sheet:adjustBar` (`sheetAdjustBarCommandDto`, estrito) ligado em `board/sheet-commands.ts` pelo `mutate` do board gateway: `onCommand` + **fila da mesa**, ack `{ ok, version }`. `SHEET_NOT_FOUND` e `SHEET_HAS_NO_TOKEN` ("This sheet is not held by a token") estão no `PUBLIC_MESSAGE` de `board-command-edge.ts`.
- `SheetBarsService.adjustBar` (deps `members`, `sheets`, `holders`, `tokens`, `characters`): lê a ficha no pool, `placeOfSheet`, `requireEdit` (Caio numa `table` → `FORBIDDEN`; ficha da Quelm, ou sem dono para quem não é mestre → `SHEET_NOT_FOUND`), `SheetItemBo.requireHolder` (o mestre numa ficha sem dono → `SHEET_HAS_NO_TOKEN`); personagem → `CharactersService.adjustBar` (`character:changed`, versão dos personagens); token solto → `TokensService.adjustBar` com o grid do token. O `adjustHolderBar` e o caminho da âncora saíram.
- `sheet:spendBars` (`sheetSpendBarsCommandDto`) pelo mesmo `mutate`, ack `{ ok, version }`. `SheetBarsService.spendBars` resolve o dono como o `adjustBar` (`heldSheet`) e entrega uma regra (`spentBarWritesOf`, `sheet-bars.bo.ts`: custo em barra que não é do dono → `BAR_NOT_FOUND` antes de qualquer saldo; depois o `spendBars` do game-core; falta → `INSUFFICIENT_BAR` `Bar "EF" has 5; expected at least 6`, a mensagem vai ao ack e à rota, 409) ao `CharactersService.rewriteBars` (personagem) ou ao `TokensService.rewriteBars` (token solto; ligado = do personagem). Os dois conferem o controle sob a própria trava, rodam a regra nas barras lidas ali e gravam tudo numa versão; regra que lança não grava nem publica. Os tipos e o `adjustedBarOf` das barras do token moram em `tokens/token-bar-writes.ts`.
- **Criar barra pela ficha** (`POST …/sheets/:s/bars`, `bars.create` do SDK): `SheetBarCreationService` (`sheet-bar-creation.service.ts`, montado no `sheets.plugin.ts`; o `sheets.service.ts` não muda). Numa transação: trava a mesa e relê a participação, acha a ficha (`SHEET_NOT_FOUND`), `requireEdit('create a bar through')`, lê o modelo e exige `character:bars` no manifesto **no servidor** (`SheetBarCreationBo.requireDeclared` → `PERMISSION_NOT_DECLARED` 403 "Sheet X needs permission character:bars; …"), sem dono → `SHEET_HAS_NO_TOKEN`. Depois o `giveManifestBars` com um manifesto de uma barra só (a mesma trava, rótulo por `barLabelKey`, cheia, até 8, uma versão) e relê as barras do dono: já havia → o id dela, `created: false`, sem gravar nem publicar; não coube → `BAR_LIMIT` 409 `Bar "Fôlego" does not fit: the holder has 8 bars; expected fewer than 8`. Publica depois do commit `character:changed` (personagem) ou `token:updated` (token solto). **Por que só com a permissão:** o jogador não cria barra à mão (as barras mudam pelo `token:update`, do mestre); a permissão que o mestre aprova ao importar o modelo é o aval, como as barras do manifesto ao dar a ficha.

## Armadilhas

- O `sheet:changed` do create chega depois da resposta HTTP: um spec que grava em seguida e espera o evento da escrita precisa de `silence()` antes de gravar os eventos, senão lê o do create.
- Apagar um token não publica `library:changed`: a ficha fica sem dono (`set null`) e a biblioteca aberta só vê isso no próximo `library:changed` ou recarga.
- Ficha de personagem sem jogador (quem saiu da mesa) sai no resumo com `tokenId` e `memberId` nulos, como uma sem dono; só mestres a leem. Distinguir pede `characterId` no `sheetSummaryDto` (mudança de contrato, não feita).

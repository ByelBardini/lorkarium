# Client · ponte do host da ficha

O lado do app da conversa com o frame: valida cada pedido, cumpre o manifesto, aplica os limites de frequência e traduz o pedido no comando real (o servidor reautoriza tudo). O SDK do frame está em [`../sheets/sandbox.md`](../sheets/sandbox.md); as mensagens em [`../sheets/contratos.md`](../sheets/contratos.md); a ficha na sala em [`sheets.md`](sheets.md). Hub: [`../sheets.md`](../sheets.md).

## Arquivos (`src/sheet-sandbox/`)

- `sheet-bridge-host.ts` — `createSheetBridgeHost`, o `state`, a ordem das guardas e os limites (`SHEET_DICE_RATE`, `SHEET_CHARACTER_RATE`, `SHEET_UPLOAD_RATE`, `SHEET_ASSET_READ_RATE`).
- `sheet-permissions.ts` (puro) — `permissionOf(type)` e `permissionRefusalOf(type, declared)`: a tabela pedido → permissão do manifesto.
- `sheet-bridge-answer.ts` — `SheetBridgeAnswer` (`{ ok: true, value? }` | `{ ok: false, code, message }`), `refusedWith`, `refusedByKind` (`too_large` → `TOO_LARGE`) e `admitted(slot, now, regra)` (o `admitInWindow` guardando os `stamps`).
- `sheet-bridge-bars.ts` — `adjustSheetBar` e `spendSheetBars` (nomes resolvidos pelo `resolveSheetBar` antes de qualquer comando).
- `sheet-bridge-character.ts` — `SheetCharacterCommands` (o `updateCharacter(scope: TableScope, …)` que o `TableBoardCommands` já tem), `sameStats`, `setCharacterStats` e `setCharacterImage`.
- `sheet-bridge-assets.ts` — `uploadSheetImage` e `readSheetAsset`.
- `sheet-preview-host.ts` — a prévia do editor (abaixo).

## `createSheetBridgeHost`

`createSheetBridgeHost({ port, campaignId, sheet, token, images, commands, characters, assets, dice, clock, diceAspect, onReady?, onConsole? })` → `{ dispose }`. `token` é o `SheetTokenSource` ou **`null` = ficha sem dono** (`state` com `token: null, bars: [], character: null`; barras → `NO_TOKEN`). Uma fonte com `current() === null` está **carregando** (nenhum `state`; barras → `NO_TOKEN` "token not loaded", personagem → `NO_CHARACTER` "character not loaded"). `images` é o `SheetsApi` (`image` e `uploadImage`), `commands` o `SheetCommands`, `characters` o `boardCommands` do app (`character:update`), `assets` o `AssetsApi` (`upload`). Na sala o `SheetPanelServices` leva `sheetsApi`, `sheetCommands`, `boardCommands`, `assets`, `dice`, `clock` (o `WorkspaceSheet` passa os do `AppDependencies`).

- Toda mensagem passa pelo `sheetFrameMessageDto`; fora dele → `INVALID_MESSAGE` com o `requestId` legível (senão `null`), sem comando.
- **Ordem das guardas:** `ready` → manifesto (`PERMISSION_NOT_DECLARED`, "character.set needs permission character:stats in the manifest", sem comando) → `dice.roll` e `assets.read` (não pedem `canEdit`: quem vê a ficha veria/rolaria à mão) → `canEdit` (`FORBIDDEN` "… refused: this sheet is read-only here") → o pedido. O manifesto é o do modelo que a store leu (`template.manifest.permissions`). Valores, barras e dados não pedem permissão.
- `ready` → `result` e o 1º `state`. Depois, o `state` vai de novo quando muda o que o frame vê do dono (nome, `imageAssetId`, barras, nome/CA/CD do personagem — comparados por valor, não pelo objeto: uma nota ou condição nova não manda nada), a imagem, os `values` ou o `canEdit`. Passa pelo `sheetHostMessageDto` antes de sair.
- Imagem do token: lida uma vez por `imageAssetId`; o `state` **espera** os bytes; falha → `image: null`.
- `values.set` → `sheet.setValues(changes)`; `values.patch` → `sheet.patchValues(patches)` (o mesmo lote de 500 ms); `result` quando salvou, senão o `kind` em maiúsculas.
- `bars.adjust` → `resolveSheetBar` (id exato; senão o rótulo por `barLabelKey`; 2+ → `BAR_AMBIGUOUS`, 0 → `BAR_NOT_FOUND`, sem dono → `NO_TOKEN`) → `commands.adjustBar`. `bars.spend` resolve **todos** os nomes primeiro (um que falha → o código dele e nada sai) → **um** `commands.spendBars(campaignId, sheetId, costs)`. Recusa do server → o código e a `message` dele quando há (o `INSUFFICIENT_BAR` cita barra, saldo e custo), senão "… refused with CODE".
- `character.set` → o personagem do dono (`token.character`; token solto ou sem dono → `NO_CHARACTER`). Valores iguais aos do personagem → `result` sem comando e **sem contar** no limite; senão `characters.updateCharacter({ campaignId }, characterId, changes)`, até 10 em 10 s (`SHEET_CHARACTER_RATE`). Recusa → `failure` em maiúsculas (`FORBIDDEN`).
- `character.setImage` → `assets.upload(campaignId, Blob, 'token')` (o processamento e o contorno do retrato de sempre) → `updateCharacter(…, { imageAssetId })`. Upload recusado → nada gravado, `TOO_LARGE`/`UNSUPPORTED`…; update recusado → o código (o asset fica órfão, como no campo de retrato da sala).
- `assets.upload` → `images.uploadImage(campaignId, sheetId, bytes, type)` → `result` com `value: { assetId }`; `assets.read` → `images.image(assetId)` → `value: { type, bytes }`; `not_found`/`forbidden` → `ASSET_NOT_FOUND`. Envios (os dois tipos somados) até 10 em 60 s (`SHEET_UPLOAD_RATE`); leituras até 120 em 60 s (`SHEET_ASSET_READ_RATE`, sem cache: uma lista longa de imagens lê cada uma). A recusa por limite não conta.
- `dice.roll` → `dice.roll(campaignId, { label: sheetRollLabelOf(template.name, label), parts, visibility, aspect })`, até 10 em 10 s; notação recusada → `INVALID_DICE_EXPRESSION`.
- `dispose()` tira os ouvintes, fecha a porta e nenhuma resposta atrasada sai.

## O dono da ficha (`sheet-token-source.ts`)

- `SheetTokenSource` = `{ current(): SheetTokenView | null; subscribe(listener) }`, `SheetTokenView` = `{ name, imageAssetId, bars, character }`, `character` = `SheetCharacterView` (`id`, `name`, `armorClass`, `difficultyClass`; o `id` fica no host) ou `null`.
- `boardTokenSource`/`firstTokenSource` (token solto: `character: null`) e `characterSource(characters, userId)` (o personagem do jogador, com `character`). As três devolvem `SheetHolderSource` (com `canControl`) e o **mesmo objeto** enquanto a store guarda o mesmo item (memória por identidade): objeto novo = o host olha de novo.
- **Decisão (o personagem):** a ficha de um personagem vem com `memberId` e `tokenId: null`; a fonte dela é `characterSource(table.characters, sheet.memberId)`; a de um token solto é a `board-store` do grid dele. Sem dono = `isSpareSheet`, ver [`characters.md`](characters.md).

## Prévia do editor (`sheet-preview-host.ts`)

`createSheetPreviewHost(port, { onConsole?, now?, permissions?, newAssetId?, data?, onDataChange? })` → `{ setData, dispose }`: um token com o nome do personagem dos **dados de teste** (`SheetPreviewData` = `{ character, bars, values }` de `src/lib/sheet-preview-data.ts`; sem `data`, o `SAMPLE_SHEET_PREVIEW_DATA`: "Exemplo", PV 20/20, CA 10, CD 10), sempre `canEdit`, e nenhum comando real. Cumpre o manifesto como a sala (`permissions` = o manifesto do rascunho; o `SheetTemplateWorkbench` lê o texto pelo `readSheetManifestText` e um manifesto inválido não concede nada; o `SheetTemplatePreview` recebe `permissions`). `values.set`/`values.patch` pelo `applySheetValueEdits`; `bars.adjust` (qualquer barra dos dados, pelo `resolveSheetBar`) pelo `adjustBarValues`; `bars.spend` pelo `spendBars` do game-core (falta → `INSUFFICIENT_BAR` com a mensagem do server; as barras sem custo ficam); `character.set` muda o personagem; cada pedido que muda os dados chama `onDataChange` com o objeto novo (recusa não chama). `setData(dados)` troca os dados e manda o `state` (depois do `ready`), sem `onDataChange`; o mesmo objeto de novo não manda nada (o eco do painel). `character.setImage` vira a imagem do token; `assets.upload` guarda os bytes com um id novo e `assets.read` os devolve (outro id → `ASSET_NOT_FOUND`); retrato e imagens são do frame, não dos dados. `dice.roll` → `PREVIEW_ONLY`. O `state` sai antes do `result`.

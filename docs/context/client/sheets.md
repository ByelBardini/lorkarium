# Client · fichas: API, store dos valores e ponte do host

Rede, store dos valores, ponte do host e a ficha na sala (aba, janela, moldura, cão de guarda, várias fichas no card e no menu do token). A ficha como item da biblioteca está em [`library.md`](library.md) (Fichas); o editor de modelo em [`sheet-template-editor.md`](sheet-template-editor.md). Hub da área: [`../sheets.md`](../sheets.md); o iframe e o SDK do frame em [`../sheets/sandbox.md`](../sheets/sandbox.md); os DTOs em [`../sheets/contratos.md`](../sheets/contratos.md). Hub do client: [`../client.md`](../client.md).

## Rede

- `src/services/sheets-api.ts` — `SheetsApi` (no `AppDependencies` como `sheetsApi`; `HttpSheetsApi(transport, fetchAssetBytes())` no `main.tsx`). Nunca lança; `SheetsResult<T>` = `{ ok, value }` | `{ ok: false, failure: { kind } }`.
  - `detail(campaignId, sheetId)` → `GET /campaigns/:c/sheets/:s` (valida o `sheetResponseDto` `{ sheet, template }`); `ofToken(campaignId, tokenId)` → `GET /campaigns/:c/tokens/:t/sheets` (valida o `tokenSheetsResponseDto` e devolve só a lista de `SheetSummaryDto`, sem valores: as fichas do token (de um ligado, as do personagem) que quem pede lê, na ordem de criação; nenhuma = `[]`);
  - `create` → `POST /campaigns/:c/sheets` (`{ actionId, templateId, name, folderId?, visibility?, holder? }`, `holder` = `{ tokenId }` | `{ memberId }`); `saveValues` → `PATCH …/sheets/:s/values` (`{ actionId, changes }`); `update` → `PATCH …/sheets/:s` (`name?`, `folderId?`, `visibility?`, `templateId?`, `holder?` com `null` = tirar do dono); os três validam o `sheetWriteResponseDto`; `remove` → `DELETE …/sheets/:s` (qualquer 2xx é `null`);
  - `image(assetId)` → os bytes de `/api/assets/:id` por um `AssetBytesReader` (`fetchAssetBytes(fetch)`: `fetch` com `credentials: 'same-origin'`), com o tipo conferido pelo `assetMimeTypeDto` (o `; charset` é ignorado; SVG ou sem tipo → `unexpected`) e no máximo `ASSET_MAX_BYTES`. O `HttpTransport` só fala JSON, por isso o leitor próprio.
  - `uploadImage(campaignId, sheetId, bytes, type)` → `POST …/sheets/:s/images` com os bytes crus num `Blob` do tipo (`callUpload`), resposta pelo `assetResponseDto` (`value` = o `AssetDto`); 413 → `too_large`, 415 e 422 → `unsupported_image`, 429 → `rate_limited`, os demais como as outras rotas. `SheetsApiFake.uploadResult` (recusado por padrão) e `uploads`.
  - `createBar(campaignId, sheetId, { bar })` → `POST …/sheets/:s/bars` (o `bars.create` da ficha), resposta pelo `createSheetBarResponseDto`; devolve `SheetBarCreationResult`, cuja recusa leva também `refusal` (o `ApiErrorDto` do server, para a ficha mostrar o código e o texto do `BAR_LIMIT`). `SheetsApiFake.createBarResult` (barra nova por padrão) e `barCreations`.
  - Recusas: `SHEET_ACTION_REUSED` → `action_reused`, `MEMBER_NOT_FOUND` → `member_not_found` (dono que não é jogador da mesa); `FOLDER_NOT_FOUND`/`TOKEN_NOT_FOUND`/`SHEET_TEMPLATE_NOT_FOUND` caem no 404 `not_found`; depois por status 400 `invalid`, 401 `unauthenticated`, 403 `forbidden`, 404 `not_found`; o resto `unexpected`; rede caída `offline`; 2xx fora do DTO `unexpected`.
- `src/services/sheet-commands.ts` — `SheetCommands.adjustBar(campaignId, sheetId, barId, change)` (no `AppDependencies` como `sheetCommands`; `RealtimeSheetCommands(realtime, newActionId)`). Emite `sheet:adjustBar` (`SHEET_EVENTS.adjustBar`) **sem** `tokenId` nem `sceneId` (o `BoardCommandSender` sempre põe o `sceneId`, por isso o envio é próprio), 5 s de paciência. `spendBars(campaignId, sheetId, costs)` emite um `sheet:spendBars` (`SHEET_EVENTS.spendBars`) com os `costs` (`SheetBarCostDto[]`, `barId` já resolvido) do mesmo jeito. Resultado `{ ok: true, version }` | `{ ok: false, code, message? }`: o código e a mensagem do server como vieram (a ponte os repassa ao frame; o `INSUFFICIENT_BAR` cita a barra, o saldo e o custo), `OFFLINE` sem ack, `UNEXPECTED` com ack fora do `boardCommandAckDto`.

## Store dos valores (`src/stores/sheet-store.ts`)

`createSheetStore({ api, campaignId, sheetId, clock, newActionId })` → `StoreApi<SheetStoreState>`, uma por ficha aberta.

- Estado: `status` (`loading` | `ready` | `not_found` | `failed`), `sheet` (confirmada), `template` (código), `values` (os confirmados com as mudanças em voo e as que esperam por cima: o que o frame vê) e `saveStatus` (`saved` | `pending` | `saving` | `offline` | `refused`).
- `load()`: 404 → `not_found` (sem ficha, sem modelo, `values: {}`: a tela desmonta); outra falha na 1ª leitura → `failed`; numa releitura mantém o que tinha. A ficha só é trocada por versão igual ou maior, o modelo idem pela versão dele.
- `changed(event)` (`sheet:changed`): outra mesa, outra ficha, versão igual ou menor, ou `not_found` → nada; versão maior → relê pela rota.
- `setValues(changes)` → `Promise<SheetValuesOutcome>`: sem `canEdit` → `forbidden`, fora de `ready` → `not_found`, sem envio. Senão junta as chaves (`null` apaga) e manda **um** patch `SHEET_VALUES_BATCH_MS` (500 ms) depois da 1ª mudança (janela fixa, não debounce: um controle arrastado sem parar ainda grava). Um envio em voo por vez; o que chega durante ele vai no próximo. A promessa resolve com o patch que levou a mudança.
- Falha do patch: `offline`/`unexpected` → o lote fica como `retry` com o **mesmo** `actionId` e vai sozinho antes das mudanças novas (o recibo idempotente do server responde se ele já tinha chegado); `not_found` → `not_found`; `forbidden`/`invalid`/`action_reused` → descarta o lote, `refused`, relê.
- `patchValues(patches)` → `Promise<SheetValuesOutcome>`: trocas por caminho (`SheetValuePathPatchDto[]`, já validadas pelo `sheetValuePathPatchesDto`) no **mesmo lote** do `setValues` (um envio `{ actionId, changes?, patches? }`, só com o que tem). Caminho sob uma chave posta no lote entra nela; chave posta depois descarta os caminhos sob ela (o server aplica `changes` antes); o mesmo caminho de novo fica só com o último; mais de 100 caminhos viram as chaves inteiras como o frame as vê. O estado otimista e o confirmado usam o `applySheetValueEdits` do contracts; o retry vai com o mesmo `actionId` e os mesmos caminhos.
- `flush()` manda já; `dispose()` cancela o timer, manda o que esperava sem ouvir a resposta e nenhuma resposta posterior mexe na store.
- Quem chama `changed`: o `WorkspaceSheet`, com o `sheet:changed` da mesa (ver Na sala).

## Na sala (`src/features/sheets/`)

- **Evento:** o `TableVisit` valida o `sheet:changed` (`sheetChangedEventDto`, estrito: com `values` cai) e entrega `{ kind: 'sheetChanged', event }`; a `scene-tabs-store` guarda o último em `sheetChange` (um objeto por evento, então quem assina vê todos).
- **Workspace:** a ficha aberta é um item `kind: 'sheet'` do `document-workspace-store` (lista `sheets`, chave `sheetWorkspaceKey` = `<campanha>:sheet:<ficha>`), aberto por `openSheet({ campaign, sheetId, sheetName })`, com uma `createSheetStore` própria (o workspace recebe `sheetsApi`). O título é "Ficha · <nome da ficha>" e **segue o nome salvo** (o `sheetName` do item é trocado quando a store lê outro nome, como o "Modelo · <nome>"). Ver o host em [`documents.md`](documents.md). 404 na releitura (excluída, dada a outro, controle perdido, virou `controllers`) tira a aba e a janela e põe `notice` "A ficha Lyra de Vharn foi fechada: ela foi excluída ou você não pode mais vê-la." (o nome atual; linha `role="alert"` do host, "Entendi"). Fechar a aba espera o `flush` dos valores.
- **`workspace-sheet.tsx`** (`WorkspaceSheet`, montado pelo host para cada item): abre a mesa, repassa o `sheetChange` da mesa ao `store.changed`, monta a fonte do dono (`characterSource` pelo `memberId`, senão `firstTokenSource(tabs.board, tokenId)`) e desenha o painel no `WorkspaceItemSurface` ("Ficha aberta em outra janela.").
- **`sheet-panel.tsx`** (`SheetPanel`): `SheetFrameChrome` + `SheetSandboxView` com `createSheetBridgeHost` (dados com `rollAspectOf` da janela). Ficha **sem dono** (`sheet.tokenId === null`, só o mestre a abre) → a ponte recebe `token: null` (o frame vê `token: null, bars: []`); com dono e o token ainda fora da sala → a fonte "carregando" (`current() === null`, nenhum `state`). O `SheetSandboxView` tem `key` pelo dono (`nobody` / `waiting` / `token:<id>`): a ficha dada, tirada ou trocada de dono enquanto aberta (o `sheet:changed` relê a store) ganha **frame e ponte novos** sobre a fonte nova, porque a ponte nunca troca de fonte sozinha; o mesmo quando a fonte da sala chega depois do frame. Remontar com a ficha pronta (ir à janela, voltar à aba) relê do servidor e cria frame novo. O token chegar sem `canControl` depois de tê-lo relê a ficha (nenhum evento diz "perdeu o controle"; o server decide: 404 fecha, `table` fica só leitura). Carregando → "Carregando ficha…"; falha → "Não foi possível abrir a ficha." + "Tentar de novo". ## Armadilhas

- `barChangeDto`: `add` leva `amount`, `set` e `max` levam `value`. O `SheetBarChange` do bootstrap espelha essa forma à mão (o arquivo é serializado no frame e não importa nada); mudou o `barChangeDto`, mude o tipo junto, senão o host recusa como `INVALID_MESSAGE`.
- Remontar um `createPortal` ↔ `<div hidden>` recria o painel: o frame da ficha sobe de novo a cada troca de aba/janela. É de propósito (relê o servidor), mas qualquer estado do frame que não esteja em `values` se perde.
- O jsdom não implementa `isContentEditable` (fica `undefined`): para reconhecer o campo do CodeMirror, use `closest('[contenteditable="true"]')`.
- Fechar a biblioteca navega numa tarefa posterior: o spec que prova que ela **não** fechou espera um `setTimeout` dentro do `act` antes de conferir o `pathname`.
- O editor de modelo remonta a cada troca biblioteca ↔ aba ↔ janela (o mesmo `createPortal` ↔ `<div hidden>`): estado que precisa sobreviver (o rascunho do código) mora na `sheet-template-draft-store`, nunca num `useState` do editor.

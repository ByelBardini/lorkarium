# Client — biblioteca de grids

A biblioteca é o modal sobre a sala onde o mestre organiza os grids (cenas) da mesa em pastas aninhadas e o jogador consulta, só em leitura, os públicos e o do grupo. O contrato REST e a regra do server estão em [`../library.md`](../library.md); aqui fica o que o client calcula e desenha.

> As abas de grid da sala estão em [`grid-tabs.md`](grid-tabs.md).

## O serviço (`src/services/library-api.ts`)

`LibraryApi` / `HttpLibraryApi(transport)` sobre o `callApi`: `list(campaignId)` → `libraryDto`; `createScene(campaignId, { name?, folderId? })`, `updateScene(campaignId, sceneId, changes)`, `duplicateScene(campaignId, sceneId)` (`POST …/copies`) → `librarySceneDto`; `removeScene` / `removeFolder` → `null` (204); `createFolder(campaignId, { name, parentId? })`, `updateFolder(campaignId, folderId, changes)` → `sceneFolderDto`. Devolve `LibraryResult<T>` (nunca lança); `LibraryFailure.kind`: pelo código `scene_is_active`, `folder_cycle`, `folder_too_deep`, `folder_not_found`; pelo status `invalid` (400), `unauthenticated` (401), `forbidden` (403), `not_found` (404: `SCENE_NOT_FOUND`/`CAMPAIGN_NOT_FOUND`); `offline`; o resto e corpo fora do DTO → `unexpected`. No `AppDependencies` como `libraryApi` (`main.tsx`: `new HttpLibraryApi(transport)`). Spec `client/test/services/library-api.spec.ts`; fixtures `test/support/library-fixtures.ts`.

## A conta da árvore (`src/lib/folder-tree.ts`, sem DOM)

Tipos **estruturais** mínimos, para não depender da forma exata dos DTOs: `TreeFolder` = `{ id, name, parentId }` e `TreeScene` = `{ id, name, folderId, visibility }`; toda função é genérica (`F extends TreeFolder`, `S extends TreeScene`) e devolve os objetos recebidos, com os campos extras (`sceneFolderDto`, `librarySceneDto`). `LibraryContents<F, S>` = `{ folders, scenes }` (a forma do `libraryDto` sem o `activeSceneId`).

- `folderTreeOf(library, groupSceneId)` → `{ roots, looseScenes }`. Cada `FolderNode` = `{ folder, depth (raiz = 1), children, scenes (diretos), sceneCount (soma as descendentes), holdsGroupGrid }`. A ordem é a recebida (o server lista na ordem de criação). `looseScenes` é o "Sem pasta". `holdsGroupGrid` marca a pasta do grid do grupo **e todas as ancestrais** (só na descrição "o grupo está aqui"; a pasta não tem marca visual).
- `filteredTreeOf(library, groupSceneId, { query, visibility })` → a árvore que a tela mostra. Sem filtro (`isFiltering` falso: busca em branco e `visibility` `'all'`) é o `folderTreeOf` inteiro, pastas vazias inclusive; com busca (sem acento nem caixa, por `searchText`) e/ou `visibility` `'public'`/`'private'`, só os grids que casam e as pastas acima deles (as contagens passam a ser as filtradas). `LibraryFilter` = `{ query, visibility }`.
- `canDrop(folders, { kind: 'folder' | 'scene', id }, destino, maxFolderDepth = SCENE_FOLDER_DEPTH_MAX)`: grid cabe em qualquer lugar; pasta não entra em si nem numa descendente e não leva a subárvore além de `maxFolderDepth` níveis (profundidade do destino + altura da subárvore). É **a mesma regra** do `SceneLibraryBo.requireMove` do server (`FOLDER_CYCLE`, `FOLDER_TOO_DEEP`) — só serve ao cursor de "não pode"; quem decide continua sendo o server. Mudou a regra num lado, muda no outro.

`src/lib/search-text.ts` — `searchText(texto)`: dobra acento e caixa; compartilhado com `filterCampaigns` (`campaign-list.ts`).

Specs: `client/test/lib/folder-tree.spec.ts`, `client/test/lib/search-text.spec.ts`.

## A rota (`src/features/library/library-route.tsx`)

- `/campaigns/:campaignId/table/library`: filha da rota da sala (`id: TABLE_ROUTE_ID = 'campaign-table'`, com `children: [índice vazio, libraryRoute(deps)]`; a sala desenha `<PlayRoomPage/>` + `<Outlet/>`). A sala continua montada debaixo do modal (o Radix só põe `aria-hidden` nela). A mesa vem do `useRouteLoaderData(TABLE_ROUTE_ID)`.
- `loader` devolve `{ library: libraryApi.list(id) }` **sem await**: o modal abre na hora com "Carregando a biblioteca…" (`role="status"`) num `<Suspense>` e `use(promise)` mostra a lista. Revalidar (ação, `library:changed`, "Tentar de novo") roda em transição: a lista velha fica na tela até a nova chegar.
- `shouldRevalidate` da sala (`keepCampaignUnderLibrary`): mesma mesa e destino em `…/table/library` → o detalhe da mesa **não** é relido.
- `action` (`library-action.ts`): JSON `{ intent, … }` validado por `libraryIntentDto` (`library-intents.ts`): `createScene`, `updateScene`, `duplicateScene`, `removeScene`, `activateScene` (pelo `sceneActivation`, `scene:activate`), `createFolder`, `updateFolder`, `removeFolder`. Responde `LibraryOutcome` = `{ intent, ok: true, createdId }` | `{ intent, ok: false, message }` (recusa já em texto: `libraryFailureMessage`, ou `tokenCommandFailureMessage` na ativação). `unauthenticated` → `signedOut` + `/login?next=…` (na lista, pelo `SignedOut` do diálogo).
- Um fetcher só (`useFetcher({ key: 'library' })`, `use-library-submit.ts`): `useLibrarySubmit()` envia; `useLibraryOutcome(onCreated)` dá `pending` (o `fetcher.json` em voo) e `refusal`, e chama `onCreated` uma vez por resposta que criou algo (grid novo ou cópia → escolhe o item e foca o nome no painel; pasta → escolhe o item).
- `library:changed` → `libraryRevision` da `scene-tabs-store` → `useRevalidateOnLibraryChange` chama `revalidate()` (`use-library-table.ts`, que também dá `live` e `playersOnline` = jogadores online pela presença).
- `AppDependencies.sceneActivation` = `SceneActivation` (`src/services/scene-activation.ts`: `RealtimeSceneActivation(transport, newActionId).activate(scope)`, ack `sceneActivateAckDto`, recusa por `boardFailureOf`).

## Arrastar (`use-library-drag.ts`)

- HTML5 nativo, sem dependência. `useLibraryDrag({ library, enabled: mestre && live, submit })` → `treeItemProps(key)` no `treeitem`: grid = só origem; pasta = origem e alvo; "Sem pasta" = alvo (`null`). Um grid não é alvo: o arraste sobre ele sobe à pasta que o contém, então soltar num grid põe na pasta dele. `aria-dropeffect` = `move`/`none` (por `canDrop`) só enquanto algo é arrastado; no proibido, `dropEffect = 'none'` e sem `preventDefault`. Soltar onde a peça já está não envia nada. O item sendo renomeado não arrasta.
- Otimista: `withPendingMove(library, pending)` põe o grid/pasta no destino enquanto o `PATCH` está em voo; a recusa traz a lista do server de volta (o item volta) e o motivo vai à linha de status.

## Armadilhas

- O jsdom não tem `DataTransfer`: o `fireEvent.dragStart(el, { dataTransfer })` só copia o objeto dado; use o `DataTransferFake`. O hook guarda o arrastado em estado (não relê o `dataTransfer` no `drop`).
- `dragstart`/`drop`/`click`/`focus` de um `treeitem` aninhado sobem para o da pasta mãe: os handlers param a propagação (ou conferem `target === currentTarget`).
- O Radix Dialog escuta o Esc no `document` em captura: o `preventDefault` do campo chega tarde. Quem impede o fechar é o `onEscapeKeyDown` do `DialogContent`.
- `DropdownMenu` que abre `Dialog` ou campo: `modal={false}` e `onCloseAutoFocus` com `preventDefault`, senão o foco volta ao gatilho por cima do campo.
- Item aberto da árvore contém os filhos: no Playwright, `click()` (e o botão direito) no `treeitem` de uma pasta aberta cai no **centro**, que é um filho (o botão direito em "Sem pasta" abriu o menu da "Cena 1"). Mire a linha do item (`position: { x: 60, y: 16 }`); no jsdom o `fireEvent` vai ao próprio elemento.
- `ContextMenuTrigger` aninhado: o Radix só abre o mais interno (o `preventDefault` do filho barra o pai), mas aí cada item precisaria do seu menu. Um gatilho só, na área, com `closest('[data-tree-key]')` no `onContextMenu` (que roda antes do do Radix), dá o alvo, inclusive pela tecla de menu sobre o item focado.
- Grid numa pasta fechada não está no DOM: no e2e, `pickGrid(biblioteca, nome)` busca o nome (a busca abre as pastas), clica e limpa a busca.

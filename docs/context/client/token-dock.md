# Client — rodapé do token (`TokenDock`) e o token do meu personagem

O rodapé da aba Combate com a ficha de um token: o selecionado ou, sem seleção, o **token do personagem** de quem vê no grid aberto e, sem ele, o próprio personagem. O personagem (store, composição, comandos) está em [`characters.md`](characters.md). Hub: [`../client.md`](../client.md); o resto dos tokens em [`tokens.md`](tokens.md).

## Componente

- `token-dock.tsx` — `TokenDock({ board, presence, characters, interaction, isMaster, onEditToken })`, fixo no rodapé do painel da aba Combate (`max-h-[58%]`, rolagem própria), em combate e fora (o `CombatPanel` passa `table.characters`). **O que mostra**: `useDockedToken` → `{ kind: 'token', token, isMain, selected }` | `{ kind: 'character', character }`: um selecionado que o viewer vê vence; senão (nada, um grupo, ou o selecionado escondido pela visão) o token do meu personagem (`mainTokenIdOf(seen, characterOfUser(characters, viewerId))`) filtrado pelo `seenTokensOf`; sem ele, o meu personagem (`CharacterDock`); sem personagem (o mestre), nada. `region` "Token selecionado" quando veio da seleção, "Token principal" quando é o token do personagem sem seleção. O principal é **só a ficha**: setas, Q/E, Delete e o anel seguem a seleção real. Corpo: "Coluna 5, linha 6 · 1 × 1 casas · Olha para o leste"; cada barra recebida (`BarLine`, `bar-line.tsx`: rótulo, "−4 / 38" em `destructive-text` — a barra em percentual, para quem controla o token (`canControl`), lê também os números, "71% · 32 / 45" (`formatBarValue(bar, { withNumbers })`); os outros só o "71%" —, o `BarTrack` (`bar-track.tsx`) com a mesma segunda barra do tabuleiro — `bg-bar-negative` / `bg-bar-over`) e, com `canControl`, a barra é o gatilho do `BarQuickEdit` (`target: { tokenId }`, "Editar PV de Lyra": duplo clique abre o balão Atual/Máx, ver [`table-people.md`](table-people.md)); sem barras, "Esse token não tem barras." (+ "Dá pra criar em Editar token." para o mestre); o `ConditionsEditor`; e o `TokenDockActions` (`token-dock-actions.tsx`): em combate, "Iniciativa de Lyra" (o `InitiativeField`) para quem `canRunEntry` da entrada do token e "Tirar do combate" (mestre, `regroupTokens` `out`); "Editar token" (mestre, ou o autor com a chave da mesa — nunca num token ligado a personagem).
- `character-dock.tsx` — `CharacterDock({ character, interaction })`: `region` "Meu personagem", o `TokenAvatar` do personagem, o nome (`h3`), "Sem token neste grid" e as barras dele (`BarLine`; com `canControl`, o `BarQuickEdit` com `target: { characterId }` → `character:adjustBar`); sem barras, "Esse personagem não tem barras.". Sem condições nem ações (não há token para elas).
- `token-dock-header.tsx` — `DockHeader({ token, isMain, isMaster?, members, interaction })`: avatar, o nome (`h3`), "Jogado por Bia"; no principal, o selo "Principal" (estrela cheia) e **sem** "Fechar ficha" (o principal é o fixo); em outro token, "Fechar ficha" (limpa a seleção e volta ao principal). A estrela "Tornar Kael meu principal" saiu (o principal é o token do personagem). Com `isMaster` (o `TokenDock` repassa o dele), o interruptor "Invisível para os jogadores" (`HiddenToggle`: `aria-pressed` = `token.hidden`, ícone `EyeOff`/`Eye`, desabilitado no `readOnly`) esconde ou revela pelo `setTokensHidden`, e a linha de status anuncia "Lobo invisível para os jogadores." / "Lobo visível para os jogadores." (ver [`hidden-tokens.md`](hidden-tokens.md)).
- Specs: `token-dock.spec.tsx` (`the viewer's character`: sem seleção a Lyra ligada da Bia com barras, o gatilho e o selo; um token solto que ela controla não é o principal; o Kael selecionado e "Fechar ficha" volta à Lyra; a própria Lyra selecionada fica com o selo; dois selecionados → o principal; o selecionado no escuro → o principal; num grid sem a Lyra, o personagem com o balão mandando `adjustCharacterBar`; personagem sem controle só lê; sem barras; o mestre sem personagem → nada) e `token-dock-header.spec.tsx` (selo, sem estrela, o interruptor do mestre: pressionado no escondido, esconder com o anúncio, revelar, o jogador sem ele, reconectando).

## Regra (`src/lib/main-token.ts`)

- `characterTokenOf(tokens, character)` → o token do grid com `characterId === character.id` (um por personagem por grid, garantido pelo server), ou `null` (sem personagem ou sem token dele ali).
- `mainTokenIdOf(tokens, character)` → o id dele. O card "Na mesa" usa o `characterTokenOf` sobre o grid do grupo ([`table-people.md`](table-people.md)).
- Quem consome passa o resultado pelo filtro de visão (`seenTokensOf`, armadilha do [`vision.md`](vision.md)).
- Spec `client/test/lib/main-token.spec.ts`.

## Sem token principal

- O `token:setMain`, o `token:mainChanged`, o `mainTokens` do board e o item "Tornar principal" saíram do client (Fase 13 do plano do personagem): o "principal" é só o token do personagem no grid aberto (`mainTokenIdOf`).

# Contracts — tabuleiro (`board/`)

Índice: [`contracts.md`](../contracts.md). Detalhe do fluxo em [`board.md`](../board.md).

- `scene.dto.ts` — `sceneGridDto` (só os campos do grid, o que o formulário do client valida); `sceneBackgroundDto` `{ assetId, width, height }` (os px da imagem: o client tira a proporção deles); `sceneDto` `{ id, name, widthCells, heightCells, cellDistance, cellUnit, gridVisible, gridOpacity, background | null }`; `configureSceneCommandDto` `{ actionId, campaignId, …grid, backgroundAssetId? }` (estrito; `backgroundAssetId`: um asset da mesa põe o fundo, `null` tira, ausente mantém). Limites: casas de `SCENE_CELLS_MIN` (1) a `SCENE_CELLS_MAX` (100), inteiras; `cellDistance` > 0 e ≤ `CELL_DISTANCE_MAX` (9999); `cellUnit` aparado, 1 a `CELL_UNIT_MAX_LENGTH` (8); `gridOpacity` inteiro de 0 a `GRID_OPACITY_MAX` (100). `SceneGridDto` = só os campos do grid.
- `board-event.dto.ts` — `boardCommandShape` (`actionId`, `campaignId`, `sceneId?`: o grid; ausente = o do grupo) e `boardEventShape` (`campaignId`, `sceneId` **obrigatório**, `version`, `at`): os campos de todo comando e todo evento do tabuleiro. O `configureSceneCommandDto` usa o `boardCommandShape`. `board.dto.ts`: `watchSceneCommandDto` (`sceneId` obrigatório; `scene:watch` responde `boardSyncAckDto`) e `sceneUnwatchAckDto` (`{ ok: true }`); `activateSceneCommandDto` (`sceneId` obrigatório; `scene:activate`) com `sceneActivateAckDto` (`{ ok: true }`, sem versão). `BOARD_EVENTS` tem `activateScene`, `sceneActivated` e `sceneClosed` (os DTOs dos dois eventos ficam em `library.dto.ts`).
- `token:draggedMany` (`tokensDraggedDto`, sem versão) leva `sceneId?` também. O server manda `sceneId` em todo evento do tabuleiro e o `boardEventShape` o exige (evento sem ele é `invalid` no client).
- `token.dto.ts` — `MAX_BARS_PER_TOKEN` (8), `TOKENS_PER_SCENE_MAX` (500, o teto da cena) e `TOKEN_LIMIT_CODE` (`'TOKEN_LIMIT'`, o código da recusa, que o server lança e o client traduz), `BAR_VALUE_LIMIT` (99 999), `TOKEN_NAME_MAX_LENGTH` (60), `TOKEN_INITIALS_MAX_LENGTH` (3), `BAR_LABEL_MAX_LENGTH` (24), `TOKEN_SIZE_MIN` (0,5), `TOKEN_SIZE_MAX` (10); `tokenSideDto` (`ally` | `enemy` | `neutral`), `barColorDto` (`gold` | `steel` | `ember` | `moss` | `ash`, nunca hex), `barVisibilityDto` (`everyone` | `controllers`), `barDisplayDto` (`number` | `percent`: "32 / 45" ou "71%", só exibição, para todos); `barInputDto` `{ label (aparado, 1–24), current (±99 999), max (1–99 999), color, visibility, display (padrão `number`) }` e `tokenBarDto` (+ `id`, `position` 0–7: a 0 é a que aparece no token); `tokenDto` `{ id, name (aparado), initials (1–3), side, width, height (0,5–10, de meia em meia), col, row (≥ 0, de meia em meia), layer, controllerIds, canControl, bars, createdBy (uuid | null: o autor, igual para todo público; `null` = token antigo ou conta apagada) }` — redigido: a barra `controllers` simplesmente não vem, e as outras guardam a `position`; comandos `createTokenCommandDto` (+ `col`, `row`, `bars`, `layer` com padrão `tokens`: no client o `NewToken` é o tipo de entrada, com `layer` opcional), `updateTokenCommandDto` (`tokenId` + campos + `bars`, sem posição), `moveTokenCommandDto` `{ tokenId, col, row }`, `adjustBarCommandDto` `{ tokenId, barId, change }` com `barChangeDto` (`{ op: 'add', amount }` | `{ op: 'set', value }` | `{ op: 'max', value }` — o máximo novo, 1–99 999; inteiros) e `deleteTokenCommandDto`; eventos `tokenCreatedDto`/`tokenUpdatedDto` `{ …, token }`, `tokenMovedDto` `{ …, tokenId, col, row }` e `tokenDeletedDto` `{ …, tokenId }`. A prévia do arraste (de um token também) é o `dragTokensCommandDto` / `tokensDraggedDto` do `token-group.dto.ts`. `canControl` num comando é recusado (estrito).
- **Direção e abertura (`direction.dto.ts`)** — `FACING_MAX` (359) e `facingDto` (inteiro de 0 a 359; recusa citando o valor e "0 to 359"; a regra é a do `facing` do game-core, reescrita aqui porque o contracts só depende do `zod`). `CONE_ANGLE_MAX` (360) e `coneAngleDto(sujeito)` (`'sight'` | `'light'`): inteiro de 1 a 360, recusa citando o sujeito e o valor, NaN incluso ("sight angle 0 is invalid; expected a whole number from 1 to 360"). Moram à parte para o `light.dto.ts` não importar o `token.dto.ts`, que já importa o `light.dto.ts` (ciclo); o `token.dto.ts`, o `token-appearance.dto.ts` e o `effect-area.dto.ts` importam daqui, e quem importa do pacote não muda.
- `token.dto.ts`, aparência — `tokenFrameDto` (`square` | `round`). O `tokenDto` leva `imageAssetId | null`, `frame`, `flipX`, `flipY`, `facing` e `defeated` (a marca de abatido; create e update a recusam: só o restyle muda), iguais para todo público (não é segredo). O `createTokenCommandDto` (e o `newTokenDto`) os aceita com padrão `null`, `square`, `false`, `false`, `0` (a colagem manda os copiados); o `updateTokenCommandDto` aceita os quatro de aparência **opcionais** (ausente mantém) e nunca o `facing` (a direção só muda pelo `token:faceMany`).
- `token-appearance.dto.ts` — `faceTokensCommandDto` `{ faces: { tokenId, facing, expect?: { facing } }[] }` (`token:faceMany`, sobre o `tokenGroupOf`; o `expect` é a precondição do desfazer) e o evento `tokensFacedDto` `{ …boardEventShape, faces: { tokenId, facing }[] }` (`token:facedMany`); `tokenStyleDto` `{ imageAssetId?: uuid | null, frame?, flipX?, flipY?, defeated?, lightLit? }` (parcial; vazio é recusado com "style is empty"; `imageAssetId: null` tira a imagem), `restyleTokensCommandDto` `{ tokenIds, style }` (`token:restyleMany`) e o evento `tokensRestyledDto` `{ …boardEventShape, tokenIds, style }` (`token:restyledMany`). Os dois eventos vão iguais à mesa toda.
- `token.dto.ts` também exporta `tokenLayerDto` (`tokens` | `objects` | `background`; a ordem do enum é a ordem de desenho, de cima para baixo) e as peças `cellIndexDto` (a posição: múltiplo de 0,5 ≥ 0) / `draggedCellDto` que os DTOs de grupo reaproveitam. `halfCellDto(noun, min, max)` é o número de meia em meia casa, recusado citando o `noun` e o valor ("token side 0.25 is invalid; expected a multiple of 0.5 from 0.5 to 10"); `tokenSideLengthDto` é o lado do token.
- `token-resize.dto.ts` — `resizeTokensCommandDto` `{ resizes: { tokenId, col, row, width, height, expect?: { col, row, width, height } }[] }` (`token:resizeMany`, sobre o `tokenGroupOf`; a caixa leva a origem porque a alça oeste/norte a move; `expect` é a precondição do desfazer) e o evento `tokensResizedDto` `{ …boardEventShape, resizes: { tokenId, col, row, width, height }[] }` (`token:resizedMany`, igual à mesa toda).
- `token-main.dto.ts` — o token principal (detalhe em [`tokens/main-token.md`](../tokens/main-token.md)): `mainTokenDto` `{ userId, tokenId }`, `setMainTokenCommandDto` `{ …boardCommandShape, tokenId, playerId? }` (`token:setMain`, estrito e **sem** `userId`: quem pede vem da conexão, §7.3; `playerId` = o jogador para quem o mestre escolhe) e o evento `mainTokenChangedDto` `{ …boardEventShape, userId, tokenId }` (`token:mainChanged`, à mesa toda).
- `member-card.dto.ts` — a ficha da mesa (detalhe em [`member-cards.md`](../member-cards.md)): `MEMBER_CARD_NAME_MAX` (40), `MEMBER_CARD_NOTE_MAX` (80), `MEMBER_CARD_STAT_MAX` (999); `memberCardDto` `{ userId, characterName, armorClass, difficultyClass, noteOne, noteTwo }` (todos nulos); `memberCardChangesDto` (parcial: texto aparado, vazio → `null`; CA/CD inteiros de 0 a 999, recusa "armorClass 1000 is invalid; expected a whole number from 0 to 999"; texto longo, "characterName has 41 characters; expected at most 40"; vazio, "changes is empty; expected at least one of …"); `updateMemberCardCommandDto` `{ …boardCommandShape, memberId, changes }` (`member:updateCard`, estrito, sem `userId`, §7.3) e o evento `memberCardChangedDto` `{ …boardEventShape, card }` (`member:cardChanged`, a ficha inteira, à mesa toda).
- `token-id-group.dto.ts` — `TOKEN_GROUP_MAX` (64), `firstRepeated(ids)`, `idGroupOf(item, idOf, noun)` (lista de 1 a 64 itens com **ids distintos**: o `superRefine` recusa citando o `noun` e o id repetido; vale para token e desenho), `tokenGroupOf(item, idOf)` (o mesmo com `noun = 'token'`), `strayExpectation(alvos, esperados)` (o id de uma precondição que não está entre os alvos) e `tokenIdGroupDto` (1 a 64 ids distintos). Arquivo próprio para o `condition.dto.ts` usar sem ciclo (`token.dto` → `condition.dto`).
- `condition.dto.ts` — condições (gravidade, aparência, ícone, descrição, rodadas, grupo, a lista da mesa): em [`condicoes.md`](condicoes.md).
- `combat.dto.ts`, a entrada de iniciativa (detalhe em [`combat.md`](../combat.md)) — `MAX_COMBATANTS` (64), `MAX_ENTRY_TOKENS` (64), `COMBATANT_NAME_MAX_LENGTH` (40). `combatantDto` `{ id, name | null, tokenIds (0–64; a ordem não é contrato), initiative, tieOrder }` (estrito: `tokenId` solto é recusado; o vínculo é sempre `tokenIds`). `combatEntryInputDto` `{ name (aparado, 1–40) | null, tokenIds (0–64), initiative (−999…999 | null, `default(null)`: cliente sem o campo segue válido; o tipo inferido o exige) }` recusa entrada sem token e sem nome ("combat entry without tokens needs a name") e token repetido citando o id; `combatEntriesDto` (1 a 64 entradas) recusa o token em duas entradas citando o id e "expected each token in one entry". `regroupTokensCommandDto` `{ tokenIds: tokenIdGroupDto, target }` com `target` (`regroupTargetDto`) = `{ kind: 'entry', combatantId }` | `{ kind: 'own' }` | `{ kind: 'out' }` (`combat:regroupTokens`); `renameCombatantCommandDto` `{ combatantId, name }` (`combat:renameCombatant`). `startCombatCommandDto` e `addCombatantsCommandDto` levam `{ entries: combatEntriesDto }` (estritos: `tokenIds` na raiz é recusado). `BOARD_EVENTS.regroupTokens` / `renameCombatant` e os dois no `BoardClientEvents`.
- `token-group.dto.ts` — comandos de vários tokens, todos sobre o `tokenGroupOf`. `moveTokensCommandDto` `{ moves: { tokenId, col, row }[] }` (`token:moveMany`, tudo ou nada, uma versão), `dragTokensCommandDto` `{ drags: { tokenId, cell | null }[] }` (`token:dragMany`, prévia do grupo), `setTokenLayerCommandDto` `{ tokenIds, layer }` (`token:setLayer`, mestre); eventos `tokensMovedDto` `{ …boardEventShape, moves }` (`token:movedMany`), `tokenLayerChangedDto` `{ …boardEventShape, tokenIds, layer }` (`token:layerChanged`, igual para a mesa toda) e `tokensDraggedDto` `{ campaignId, at, drags }` (`token:draggedMany`, **sem `version`**: é prévia, não mudança confirmada).
- `token-group.dto.ts`, lote e precondição do desfazer — `newTokenDto` (o corpo do `token:create` sem `actionId`/`campaignId`, mais `combatantId?` uuid: a entrada de combate do original copiado; `NewTokenInput` com `layer` opcional), `createTokensCommandDto` `{ tokens: 1–64 }` (`token:createMany`, mestre, colar), `deleteTokensCommandDto` `{ tokenIds, expect?: { tokenId, col, row }[] }` (`token:deleteMany`; `expect` de um id fora do `tokenIds` é recusado citando o id), e `expect?: { col, row }` em cada item do `moveTokensCommandDto` (`TokenMoveDto`). Eventos `tokensCreatedDto` `{ …boardEventShape, tokens, combat | null }` (`token:createdMany`, por público; `combat` obrigatório: o combate depois que as cópias entraram nas entradas dos originais) e `tokensDeletedDto` `{ …boardEventShape, tokenIds, combat | null }` (`token:deletedMany`). O `tokensMovedDto` não leva `expect`.
- **Visão e caminho** — `scene.dto.ts`: `sceneVisionDto` (`off` | `dark` | `daylight`) e `vision?` no `configureSceneCommandDto` (ausente mantém o modo). `token.dto.ts`: `SIGHT_RANGE_MAX` (100) e `sightDto` `{ bright, dim }` (cada um finito de 0 a 100 casas; recusa citando o lado e o valor, NaN incluso: "sight bright 100.5 is invalid; expected 0 to 100 cells"; a regra do `sightRange` do game-core reescrita); `sight?: sightDto | null` no `createTokenCommandDto` (e no `newTokenDto` da colagem) e no `updateTokenCommandDto` (ausente mantém; `null` = não enxerga). **Campo de visão:** `sightAngle` (`coneAngleDto('sight')`) fica **fora** do `sight` (o token cego também olha em cone): obrigatório no `tokenDto` (igual para todo público), `default(360)` no create e na colagem, opcional no update (ausente mantém; só o mestre manda). `MOVE_PATH_MAX` (32) e `movePathDto` (as curvas `{ col, row }[]` entre a origem e o destino, recusa citando "path has 33 bends; expected at most 32") como `path?` no `moveTokenCommandDto` e em cada item do `moveTokensCommandDto`.
- **Precondição (`expect`).** Opcional nos comandos de mover e apagar (token e desenho). O comando normal não manda; o inverso do desfazer manda sempre. O server confere dentro da transação que trava a cena: diferente do gravado → `STALE_UNDO` ("o estado mudou desde a ação desfeita"). O `code` do `apiErrorDto` é string livre: os códigos não são enum no contrato.
- `drawing.dto.ts` — o desenho (detalhe em [`drawings.md`](../drawings.md)). Limites: `DRAWING_POINTS_MAX` (2000 pontos por mão livre), `DRAWINGS_PER_SCENE_MAX` (500, conferido no server), até `TOKEN_GROUP_MAX` desenhos por comando. `drawingColorDto` (8: `gold`, `steel`, `ember`, `moss`, `ash`, `ink`, `bone`, `violet`; nunca hex), `strokeWidthDto` (`thin` | `medium` | `thick`), `fixedShapeKindDto` (`rectangle` | `ellipse` | `triangle`). `drawingShapeDto` é união por `kind`: `freehand` `{ x, y, width ≥ 0, height ≥ 0, points: [x, y][] }` (pontos relativos a `(x, y)`, de 2 a 2000, cada um dentro da caixa com 0,01 de folga; recusa citando a contagem ou o ponto) ou forma fixa `{ kind, x, y, width > 0, height > 0, fill: cor | null (padrão null) }`; as duas com `stroke`, `strokeWidth` e **sem camada** (`layer` enviado é recusado, estrito). **Preenchimento só em forma fixa**: `fill` na mão livre é recusado (estrito). Coordenadas em casas fracionárias de 0 a `SCENE_CELLS_MAX`. `drawingDto` = forma + `id` + `authorId | null`. Comandos `createDrawingsCommandDto` `{ drawings }` (`drawing:createMany`), `moveDrawingsCommandDto` `{ moves: { drawingId, x, y, expect?: { x, y } }[] }` (`drawing:moveMany`, ids distintos), `deleteDrawingsCommandDto` `{ drawingIds, expect?: { drawingId, x, y }[] }` (`drawing:deleteMany`); eventos `drawingsCreatedDto` `{ drawings }`, `drawingsMovedDto` `{ moves: { drawingId, x, y }[] }`, `drawingsDeletedDto` `{ drawingIds }`. `authorId` num comando é recusado (estrito, §7.3).
- `effect-area.dto.ts` — a área de efeito (detalhe em [`effect-areas.md`](../effect-areas.md)). `EFFECT_AREAS_PER_SCENE_MAX` (100, conferido no server), `EFFECT_AREA_REACH_MAX` (= `SCENE_CELLS_MAX`), até `TOKEN_GROUP_MAX` áreas por comando. `effectAreaKindDto` (as 9 formas). `effectAreaShapeDto` é união estrita por `kind` em quatro famílias: `square` `{ x, y, width, height }`, redonda (`circle` | `smooth_circle`) `{ x, y, reach }`, apontada (`semicircle` | `orthogonal_cone` | `diagonal_cone` | `line` | `smooth_semicircle`) `{ x, y, reach, facing }` e `emanation` `{ x, y, width, height, reach }`, todas com `color` (`drawingColorDto`). O `superRefine` reescreve a regra do `effectArea` do game-core com as mesmas mensagens (origem, raio, lados e direção por forma; ver `game-core.md`, Área de efeito). `effectAreaDto` = forma + `id` + `authorId | null`. Comandos `createEffectAreasCommandDto` `{ effectAreas }` (`effectArea:createMany`; `authorId` recusado, §7.3), `reshapeEffectAreasCommandDto` `{ reshapes: { effectAreaId, shape, expect?: forma }[] }` (`effectArea:reshapeMany`: mover, esticar e girar mandam a forma inteira; ids distintos; o `expect` pode ser de outra forma) e `deleteEffectAreasCommandDto` `{ effectAreaIds, expect?: { effectAreaId, shape }[] }` (`effectArea:deleteMany`; `expect` de id fora da lista recusado citando o id). Eventos `effectAreasCreatedDto` `{ effectAreas }`, `effectAreasReshapedDto` `{ reshapes: { effectAreaId, shape }[] }`, `effectAreasDeletedDto` `{ effectAreaIds }`.
- `wall.dto.ts` — a parede (detalhe em [`walls.md`](../walls.md)). Limites: `WALLS_PER_SCENE_MAX` (500), `WALL_POINTS_MAX` (500 pontos por mão livre), `WALL_SEGMENTS_PER_SCENE_MAX` (4000 segmentos por cena, o círculo conta 32; conferidos no server), até `TOKEN_GROUP_MAX` paredes por comando. `wallKindDto` (`wall` | `grate` | `curtain` | `door`), `wallShapeKindDto` (`line` | `freehand` | `rectangle` | `ellipse`), `doorStateDto` (`closed` | `open` | `locked`). `wallShapeDto` é união estrita por `shape`: reta e mão livre `{ kind, x, y, width ≥ 0, height ≥ 0, points: [x, y][] }` (relativos a `(x, y)`; reta com 2, mão livre de 2 a 500, cada um dentro da caixa com 0,01 de folga), quadrado e círculo `{ kind, x, y, width > 0, height > 0 }`. O `superRefine` reescreve a regra do `wall` do game-core com as mesmas mensagens ("line has 3 points; expected 2", "point (5, 0) is outside the 4 × 0 box", "door must be a line; got rectangle"). `doorState` e `authorId` no comando são recusados (estrito: o server põe a porta `closed`; a parede não tem autor). `wallDto` = forma + `id` + `doorState | null` (porta sem estado e parede com estado recusadas citando o valor). Comandos `createWallsCommandDto` `{ walls }` (`wall:createMany`), `moveWallsCommandDto` `{ moves: { wallId, x, y, expect?: { x, y } }[] }` (`wall:moveMany`, ids distintos), `deleteWallsCommandDto` `{ wallIds, expect?: { wallId, x, y }[] }` (`wall:deleteMany`), `setWallKindsCommandDto` `{ wallIds, kind, expect?: { wallId, kind }[] }` (`wall:setKindMany`) — `expect` de id fora da lista recusado citando o id — `setDoorCommandDto` `{ wallId, state }` (`wall:setDoor`) `eraseWallAreaCommandDto` `{ box: { x, y, width > 0, height > 0 } }` (`wall:eraseArea`, ack com `createdIds` do que sobrou) e `eraseWallSegmentCommandDto` `{ wallId, segmentIndex (inteiro 0..WALL_SEGMENTS_PER_SCENE_MAX), expect?: { x, y } }` (`wall:eraseSegment`, ack com `createdIds` do que sobrou). Eventos `wallsCreatedDto` `{ walls }`, `wallsMovedDto` `{ moves: { wallId, x, y }[] }`, `wallsDeletedDto` `{ wallIds }`, `wallSegmentErasedDto` `{ wallId, walls: wallDto[] }`, `wallAreaErasedDto` `{ wallIds (até 500), walls: wallDto[] }`, `wallKindsChangedDto` `{ changes: { wallId, kind, doorState }[] }` e `doorChangedDto` `{ wallId, doorState }`, todos à mesa inteira.
- `board.dto.ts` — `BOARD_EVENTS` (`board:sync`, `scene:configure`, `scene:updated`, `token:create|createMany|update|move|moveMany|dragMany|setLayer|faceMany|restyleMany|resizeMany|adjustBar|setMain|delete|deleteMany`, `token:created|createdMany|updated|moved|movedMany|draggedMany|layerChanged|facedMany|restyledMany|resizedMany|deleted|deletedMany|mainChanged`, `member:updateCard`, `member:cardChanged`, `drawing:createMany|moveMany|deleteMany`, `drawing:createdMany|movedMany|deletedMany`, `effectArea:createMany|reshapeMany|deleteMany`, `effectArea:createdMany|reshapedMany|deletedMany`, `wall:createMany|moveMany|deleteMany|setKindMany|setDoor`, `wall:createdMany|movedMany|deletedMany|kindsChanged|doorChanged`, `light:createMany|moveMany|setRangeMany|setColorMany|setConeMany|setLitMany|deleteMany`, `light:createdMany|movedMany|rangesChanged|colorsChanged|conesChanged|litChanged|deletedMany`); `boardCommandDto` `{ actionId, campaignId }` (base de todo comando e payload do `board:sync`); `boardStateDto` `{ campaignId, version, at, viewer: { userId, role }, scene, tokens: TokenDto[], drawings: DrawingDto[], effectAreas: EffectAreaDto[], walls: WallDto[], lights: LightDto[], combat, conditionDefinitions, mainTokens: MainTokenDto[], memberCards: MemberCardDto[] }` (snapshot já redigido para quem pede); `boardSyncAckDto` (`{ ok: true, state }` | falha); `boardCommandAckDto` (`{ ok: true, version, createdIds? }` | falha; `createdIds` só no ack de `token:createMany`, `drawing:createMany`, `effectArea:createMany`, `wall:createMany` e `light:createMany`: os ids que o server deu, na ordem enviada — o desfazer de quem criou precisa deles); `sceneUpdatedDto` `{ campaignId, version, at, scene }`; `BoardClientEvents` / `BoardServerEvents` e `TableClientEvents` / `TableServerEvents` (sessão + tabuleiro + dados; o do server também a biblioteca; os genéricos do Socket.IO).
- **Alcance (`reach.dto.ts`)** — `REACH_MAX` (100) e `reachSideDto(sujeito, lado)`: um lado do alcance (número finito de 0 a 100 casas; NaN passa ao `refine` para a recusa citá-lo), recusado com "light bright 101 is invalid; expected 0 to 100 cells" ou "sight …". É a peça do `sightDto` e do `lightRangeDto`.
- **Luz do token** — `light.dto.ts`: `LIGHT_RANGE_MAX` (100) e `lightRangeDto` `{ bright, dim }` (estrito; a regra do `lightRange` do game-core reescrita). `tokenLightDto` = `lightRangeDto` + `color` (`lightColorDto` nulo, ausente vira `null`: a Neutra) + `angle` (a abertura do feixe, `coneAngleDto('light')`, ausente vira 360; o cone olha para o `facing` do token). `token.dto.ts`: o `tokenDto` leva `light: tokenLightDto | null` (`null` = não emite luz) e `lightLit: boolean`, iguais para todo público (o client precisa deles para a névoa). `light?: tokenLightDto | null` no `createTokenCommandDto` (e no `newTokenDto` da colagem) e no `updateTokenCommandDto` (ausente mantém; `null` tira a luz e a cor; só o mestre manda, então só ele muda a cor). O create **não** aceita `lightLit`: o token novo (e a cópia) nasce aceso. `lightLit?` no `tokenStyleDto`: quem controla acende e apaga pelo `token:restyleMany`, como o `defeated` (a mensagem do estilo vazio cita `lightLit`).
- **Luz do mapa (`light.dto.ts`)** — a tocha na parede, a fogueira (detalhe em [`lights.md`](../lights.md)). `LIGHTS_PER_SCENE_MAX` (100, conferido no server). **Cor:** `LIGHT_COLORS` (`torch`, `candle`, `fire`, `moon`, `arcane`, `necrotic`, `infernal`) e `lightColorDto` (o nome da paleta, nunca hex; os tons moram no client; a luz Neutra é `color: null`). `lightPlacementDto` `{ x, y, bright, dim, color, facing, angle }` (o ponto em casas fracionárias de 0 a `SCENE_CELLS_MAX`; `color` ausente vira `null`, como o `fill` do desenho; `facing` ausente vira 0 e `angle` ausente vira 360; a luz nasce acesa, então `lit` é recusado) e `lightDto` `{ id, x, y, bright, dim, lit, color, facing, angle }` (as chaves `color`, `facing` e `angle` são obrigatórias no evento), igual para todo público (o client do jogador precisa dele para a névoa; só o tabuleiro do mestre desenha o ícone). Comandos (só o mestre), todos tudo ou nada numa versão e com até 64 itens (`idGroupOf(…, 'light')`): `createLightsCommandDto` `{ lights }` (`light:createMany`, ack com `createdIds`), `moveLightsCommandDto` `{ moves: { lightId, x, y, expect?: { x, y } }[] }`, `setLightRangesCommandDto` `{ changes: { lightId, bright, dim, expect?: { bright, dim } }[] }` (`light:setRangeMany`), `setLightColorsCommandDto` `{ changes: { lightId, color, expect?: { color } }[] }` (`light:setColorMany`; `color: null` volta à Neutra; entra no desfazer, como o alcance), `setLightConesCommandDto` `{ changes: { lightId, facing, angle, expect?: { facing, angle } }[] }` (`light:setConeMany`; mira e abre o holofote; entra no desfazer), `setLightsLitCommandDto` `{ lightIds, lit }` (`light:setLitMany`, sem `expect`: acender é ação de jogo, fora do desfazer) e `deleteLightsCommandDto` `{ lightIds, expect?: { lightId, x, y }[] }` (`expect` de id fora do comando é recusado: "light X is not being deleted; expected only ids in lightIds"). Eventos: `lightsCreatedDto` `{ lights }`, `lightsMovedDto` `{ moves: { lightId, x, y }[] }`, `lightRangesChangedDto` `{ changes: { lightId, bright, dim }[] }`, `lightColorsChangedDto` `{ changes: { lightId, color }[] }` (sem `expect`), `lightConesChangedDto` `{ changes: { lightId, facing, angle }[] }` (`light:conesChanged`, sem `expect`), `lightsLitChangedDto` `{ lightIds, lit }`, `lightsDeletedDto` `{ lightIds }`. `lights: LightDto[]` no `boardStateDto`.
- **Token invisível** (`token-hidden.dto.ts`; plano `docs/plans/2026-10-24-token-invisivel.md`) — `tokenDto.hidden` (obrigatório: o server sempre manda; só o mestre e os controladores recebem o token escondido); `newTokenDto.hidden` (padrão `false`: colar e o desfazer de uma exclusão levam o estado da origem; o `createTokenCommandDto` do "Novo token" **não** o aceita). `setTokensHiddenCommandDto` `{ …boardCommandShape, tokenIds (tokenIdGroupDto), hidden }` (`token:setHiddenMany`, mestre); eventos `tokensHiddenChangedDto` `{ …boardEventShape, tokenIds, hidden }` (`token:hiddenChanged`, a quem vê os tokens; o resto recebe `token:deletedMany` / `token:createdMany`) e `veiledLightsChangedDto` `{ campaignId, sceneId, at, lights }` (`token:veiledLightsChanged`, **sem versão**: a lista inteira substitui a anterior). `light.dto.ts`: `veiledLightDto` `{ x, y, bright, dim, color, facing, angle }` (a luz acesa de um token que o viewer não recebe, pelo centro em casas fracionárias; sem id nem tamanho) e `boardStateDto.veiledLights`. `board-event.dto.ts`: `boardAdvancedDto` (= `boardEventShape`, `board:advanced`: a versão andou e nada dela é para quem recebe; mantém a versão sem buraco).

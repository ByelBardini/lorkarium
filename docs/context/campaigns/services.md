# Services de mesas

Detalhe de [`../campaigns.md`](../campaigns.md): a orquestração de cada caso de uso do módulo `campaigns` (criar, listar, detalhe, configurações, participação em memória, entrada). A troca de papel está em [`papeis.md`](papeis.md) e o juggernaut em [`juggernaut.md`](juggernaut.md).

- `CampaignsService` (`CampaignsServiceDeps`: DAOs de leitura, `presence: PresenceReaderPort`, `transaction: CampaignTransactionRunner`, `codes`, `hasher`, `clock`):
  - `create(userId, dto)`: hash da senha (se houver) → até 3 tentativas, cada uma **numa transação própria** (a violação de unicidade aborta a transação no Postgres): gera o código, grava a mesa, o criador como `master` (`joinedAt` do relógio) **a cena ativa** (`scenes` com o grid padrão + `campaigns.active_scene_id`, ver `../board.md`) e **o elenco** (`kind = 'cast'`, ver `../tokens/character.md`), tudo na mesma transação; `23505` → próximo código; 3 colisões → `CampaignCodeExhaustedError` citando os códigos. Devolve o detalhe.
  - `listMine(userId)` e `detail(userId, campaignId)` (participação → `requireMember` → mesa → membros → elenco: `castSceneId` pelo `ScenesDao.findCastOf`, dep `scenes` → `lastAccessAtOf` → `presence.onlineUserIdsOf`). `create` aceita `status` e a capa desenhada.
  - `campaignIdsOf(userId)` → os ids das mesas do usuário (só as participações dele): a entrada da sessão ao vivo para avisar cada mesa de um perfil gravado (`session:memberUpdated`, ver `../sessions.md`).
  - `rosterOf(userId, campaignId)` → `CampaignMemberRow[]` (com o perfil, em `orderedMembers`): participação → `requireMember` → membros, os dois pelo `memberships` (dep `memberships: MembershipReader`), de modo que o `session:join` deixa a participação lembrada para os comandos do tabuleiro. É a porta de entrada de **outro módulo** (a sessão ao vivo, `../sessions.md`) aos membros da mesa; quem não é membro recebe `CampaignNotFoundError` sem chegar ao `listMembers`.
- `CampaignSettingsService` (`campaigns`: `update`/`replaceJoinCode`/`delete`, `members.findMembership` sem memória, `assets.findInCampaign`, `detail` = o `CampaignsService`, `memberships.forgetCampaign`, `changed: CampaignChangedPort`, `presence: PresenceReaderPort`, `codes`, `hasher`, `clock`), só mestre com a mesa aberta (participação + `presence.onlineUserIdsOf(id).has(userId)` → `CampaignSettingsBo.requireMasterAtTable`) e **persiste antes de avisar**:
  - `update(userId, id, dto)`: capa imagem → `findInCampaign` → `requireCoverImage`; senha → `passwordChange` → hash só no `replace`; `update` com `updatedAt` do relógio → detalhe relido → `changed.campaignUpdated(toCampaignInfoDto(detalhe))`.
  - `regenerateJoinCode(userId, id)`: até `MAX_CODE_ATTEMPTS` (3, exportado do `campaigns.service.ts`) `replaceJoinCode`, `23505` → próximo; 3 colisões → `CampaignCodeExhaustedError`. Avisa como o `update` (o evento não leva o código).
  - `delete(userId, id)`: `delete` → `memberships.forgetCampaign(id)` → `await changed.campaignDeleted(id)`.
- **Participação em memória** (`CachedMemberships(dao, limite = MEMBERSHIP_MEMORY_MAX` = 4096)): `findMembership` lembra só quem **é** membro (por `<mesa>:<usuário>`, então membro da mesa A não vale para a B); "não é membro" vai ao banco toda vez, para quem entra pelo código logo depois ser aceito. No limite a memória recomeça (`clear`). `listMembers` não é lembrado (muda quando alguém entra). `forget(mesa, usuário)`: a troca de papel e o liga/desliga do juggernaut chamam (`MemberRoleService`, `JuggernautService`); **quando nascer expulsar, o caso de uso chama `forget` junto**, senão quem saiu segue mandando comando no tabuleiro com o papel velho. `forgetUser(usuário)` esquece todas as mesas da pessoa: o backoffice chama ao excluir uma conta (ver `../user-admin.md`). `forgetCampaign(mesa)` esquece todos da mesa: a exclusão da mesa chama. O próprio módulo (detalhe, `enter`, entrada por código) segue no DAO sem memória: lê `lastEnteredAt`, que a memória deixaria velho. Vale em instância única (spec §5.7).
- `CampaignJoinService` (DAOs, `hasher`, `clock`): `join(userId, { code, password? })` e `joinPublic(userId, campaignId, { password? })` (acha pelo id e chama `requirePublic`; admin entra em privada e sem senha, `readerIsAdmin`) passam pelo mesmo `admit`; o `join` acha pelo código (senão `CampaignNotFoundError` citando o código), verifica a senha só quando `needsPasswordCheck()`, grava `spectator` e devolve o resumo (o `memberCount` sem ele); `enter(userId, campaignId)` aceita qualquer participação (`requireViewer`) e grava `last_entered_at` com o relógio.
- O runner de transação (`CampaignTransactionRunner`) entrega DAOs presos ao `tx` (`campaigns`, `members`, `scenes`); o plugin o monta sobre `runInTransaction`.
